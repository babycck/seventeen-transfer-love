# 换乘恋爱 × SEVENTEEN — 完整规则书（终版 v3.2）

---

## 一、节目本质

```
        女主（唯一女性参与者）
              │
    ┌─────────┼─────────┐
    │         │         │
 💔 前任 X   攻略对象A   攻略对象B
 (1人)      (各有场外X)  (各有场外X)
    │         │         │
    └────?────┴────?────┘
         复合 or 换乘？
```

**核心设定**：1 位女主 + 3 位 SEVENTEEN 成员。其中 1 人是女主的秘密前任 X（恋爱 2 年，分手 1 年），其余 2 人各有场外女性 X（不在节目中出场）。2 位攻略对象之间无 X 关系。

**X 身份**：女主和 X 当年是**秘密恋爱，团内无人知晓**。所有成员（包括 X 的队友）都不知道这段关系。X 身份对所有参与者都是秘密。

**「换乘」的含义**：女主在 12 天节目结束后，是选择回到前任身边（复合），还是走向新的人（换乘）。这是唯一的情感主线。

**叙事视角**：女主单一视角。2 位攻略对象的场外 X 仅作为背景存在——解释他们为何参加节目，但节目的情感弧线始终围绕女主展开。场外 X 虽然不出场，但需要被感受到：Day 3 故事中隐约涉及、采访间流露复杂情绪、观察员偶尔推测。

### 3.3 女主人设对剧情的驱动（强制执行）

| 人设要素 | 剧情中的体现 |
|----------|-------------|
| 职业 | 自然地穿插在剧情中——对话中可能被问起、场景中可能涉及相关工作、成员可能对她的职业表示好奇。不需要每段都提，但不要完全忽略。职业是角色的一部分，不是标签 |
| 星座 | 偶尔作为轻松话题提及，不深度分析。观察员可以偶尔分析星座配对，但不做星座算命 |

| 外貌特征 | 在场景中自然地出现——某人可能注意到她的某个特征，或者某个特征在特定情境下被凸显。不强制频率 |
| 私密体质 | 在相关场景中自然触发。如「怕黑」→ 深夜场景中下意识开灯或靠近他人；「泪失禁」→ 情绪激动时控制不住流泪；「易醉体质」→ 喝酒后容易醉。不在无关场景中强行提及。**每次 prompt 注入私密体质提醒** |

### 3.4 性格行为映射表（AI 内部参考·强制执行）

| 性格标签 | 剧情行为映射 |
|----------|-------------|
| 慢热但一旦爱了就全力以赴 | 初期（Day 1-5）选项偏保守、回避直接表达好感；后期（Day 6-12）某个关键节点出现一次突破性的主动行为——可能是一句直白的话、一次主动的靠近、一条大胆的短信。转折点前后有明显反差 |
| 社恐小透明 | 集体场景中倾向于坐在边缘位置；被多人注视时会耳朵红、低头、语速变快或变慢；轮流发言时最后一个开口；在采访间中比在正文中更流畅地表达。但随着天数推移，紧张程度逐渐降低。**喝酒后暂时不再社恐——话变多、大胆直视、主动靠近，酒醒后在采访间里震惊于自己刚才的表现** |
| 外冷内热 | 表面反应平淡，但内心活动极其丰富。正文中她的回应简短克制，采访间中却暴露出大量细腻的感受。成员可能误读她的冷淡为「不感兴趣」，直到某个瞬间发现她其实一直在意 |
| 温柔细腻 | 会第一个注意到成员的情绪变化（谁今天话少了、谁在强颜欢笑）；会在恰当的时机做出恰当的小举动（递一杯水、留一盏灯、说一句「你还好吗」）；成员对她的评价常包含「治愈」「安心」 |
| 偶尔毒舌 | 对逐渐熟悉的成员会有调侃和吐槽，但分寸精准不伤人。毒舌后常有微小的补救动作（补一句软话、递个东西）。在采访间中可能自嘲「我是不是说得太过分了」。是关系亲近的信号——越熟越毒舌 |
| 共情力强 | 容易被他人情绪感染——看到成员难过会跟着眼眶泛红；听到感动的故事会沉默很久；在冲突场景中会感到强烈的不适并试图缓和。采访间中经常反思「他当时那样说，是不是因为……」 |
| 独立要强 | 不习惯向他人求助，即使需要帮助也会先尝试自己解决。在节目中可能显得「不需要照顾」，让保护欲强的成员（如崔胜澈）感到无从下手。但在某个脆弱时刻会意外地向信任的人袒露柔软一面 |
| 活泼开朗 | 笑声是她的标志。在集体场景中是气氛的润滑油，会主动开启话题、活跃僵局。但过于开朗可能让内向型成员（如全圆佑、文俊辉）需要时间适应。采访间中可能暴露「其实我也有安静的时候」 |
| 敏感多疑 | 会过度解读成员的一句话、一个眼神——「他刚才那样说是什么意思？」「他是不是对另一个人更有好感？」。采访间中充满自我怀疑。需要成员用明确的行动来打消她的不安 |
| 直率坦诚 | 不喜欢暧昧和猜测，会直接表达自己的感受和疑问。在节目中可能打破暧昧气氛——直接问「你刚才说的是认真的吗？」。某些成员会被这种直率吸引，某些可能被吓到 |
| 浪漫理想主义 | 对爱情有美好的想象和期待。会被小细节打动——一首歌、一句话、一个眼神。但也容易因为现实与理想的落差而失望。采访间中常有诗意的表达 |
| 务实理性 | 用理性分析感情，会在心里衡量「这段关系有没有未来」「我们合不合适」。在最终选择时更倾向于「换乘」而非「复合」。采访间中的表达条理清晰，像在分析一个项目 |
| 占有欲强 | 对有好感的人表现出明显的占有欲——看到他和别人互动会不舒服，会下意识地靠近他、打断对话、或者用眼神"宣示主权"。采访间中坦诚「我就是不想他和别人太亲近」。吃醋剧情更强烈，与照顾型成员（崔胜澈）可能形成"谁更占有欲"的张力 |
| 被动等待型 | 不主动出击，但内心期待对方来找自己。会故意在对方可能出现的地方待着，却不主动打招呼。采访间中充满「他会不会来找我」「他为什么不主动」的纠结。需要对方足够主动才能打破这层壳 |
| 嘴硬心软 | 说话时语气强硬、可能说反话（「我才不在意呢」），但行动上却温柔体贴。被对方看穿时会恼羞成怒。采访间中承认「其实我刚才说的不是真心话」。与毒舌型成员（全圆佑、夫胜宽）形成有趣的"嘴硬对决" |
| 撒娇体质 | 自然地撒娇，不是刻意而是本能——累了会靠在别人身上、饿了会嘟嘴、想要什么会用软软的语气说。年下成员（李灿）可能被这种撒娇"击倒"，温柔型成员（尹净汉）会享受被撒娇的感觉。采访间中可能自嘲「我是不是太黏人了」 |
| 好奇心旺盛 | 对成员的一切都好奇——他的过去、他的习惯、他为什么这样说话。会主动提问、探索、观察。推动剧情发展，因为好奇心会让她主动靠近成员。采访间中充满「我想知道更多关于他的事」 |
| 回避型依恋 | 想靠近又害怕亲密关系——当关系升温时会本能后退，当对方冷淡时又想靠近。形成复杂的情感张力。采访间中暴露矛盾「我明明想靠近，但靠近了就想逃」。适合虐心剧情，与深情型成员可能形成"追-逃"模式 |
| 讨好型人格 | 总是想让对方开心，会迁就对方的喜好、压抑自己的需求。可能被某些成员察觉并心疼，也可能被某些成员误解为"没有个性"。采访间中反思「我是不是太忽略自己了」。与独立型成员形成对比，可能被对方提醒「你也可以表达自己的需求」 |
| 记仇小本本 | 会记住对方的小失误——谁说过的话没兑现、谁曾经忽略了她。不是恶意记仇，而是心里有个"小账本"。偶尔翻旧账时会让对方措手不及。采访间中可能吐槽「他上次明明说……」。与某些成员形成有趣的日常互动 |

## 六、X 关系全貌（3 层档案）

### 6.1 档案结构

| 层级 | 内容 | 可见性 |
|------|------|--------|
| 主故事 | 相识经过（≥200字）+ 恋爱关键回忆（≥400字，≥2场景）+ 分手原因（≥200字） | 玩家可见（X档案弹窗） |
| 隐藏情感 | 每场景的意义 + X 当前隐藏情感（≥250字） | 仅 AI 内部使用 |
| 记忆物品（场内X） | 3-5 件与具体场景关联的物品 | Day 4/6 分批公开 |
| 场外 X 档案 | 攻略对象↔场外X：基本信息 + 分手原因（≥150字） | 玩家可见 |
| 记忆物品（场外X） | 2-3 件与分手故事关联的物品 | **仅 AI 调用至 Day 4/6，玩家不可见** |

### 6.2 生成规则

**人物驱动（非模板化）**：
- 相识场景必须与女主职业相关
- 至少 2 个女主外貌特征在相识时被对方注意到
- 成员性格关键词和情感模式必须在故事中体现
- 至少 2 个成员关键细节在故事中出现
- 分手原因必须是两人性格碰撞的必然结果，禁止「聚少离多」「性格不合」等通用理由

**记忆物品**：
- 女主↔X：3-5 件，与具体场景直接关联
- 攻略对象↔场外X：2-3 件，与分手故事中的具体场景关联。**存入 `GS.xItems[memberId]`，仅 Day 4/6 prompt 注入，不在 X 档案弹窗中展示**
- 所有记忆物品在 Day 4（第一批）和 Day 6（第二批）分批公开

**禁止项**：
- 通用相识场景（书店偶遇、咖啡厅邂逅）
- 忽略任何一方性格
- 概括性词语（「经常」「总是」「每次」→ 必须写「有一次」「那一天」）
- 「他们相爱了两年」→ 写具体怎么相爱

| Day 3 | ⚠️ **每人说一个关于自己的故事或秘密**（制作组安排）。故事必须由人物性格驱动：X 的故事可能隐约涉及过去但不暴露身份；攻略对象的故事反映他们的第二职业或性格特质 |
| Day 4 | 上午：**第一次约会配对**（骰子）。制作组公开**第一批 X 记忆**（4人各自的物品分批公开）。下午：约会 |
| Day 5 | 上午：**第二次约会配对**（骰子）。下午：约会。傍晚：约会归来交流 |
| Day 6 | 制作组公开**第二批 X 记忆**（更明显），有人开始确认猜测 |
| Day 7 | 集体外出活动（制作组安排），全员参与 |
| Day 8 | 上午：**第三次约会配对**（骰子）。下午：约会。傍晚：约会归来交流。今晚起短信可以发给 X |
| Day 9 | ⚠️ **X 约会日**！强制与 X 约会。X 当面读分手后写的信——这封信必须克制、真诚、不煽情，参考 X 档案中的隐藏情感和分手原因。这是情感高潮 |
| Day 10 | 自由约会——由你指定跟谁约会 |
| Day 11 | 上午：最终约会。傍晚：⚠️ **真心话环节**（详见第九章）。深夜：醉酒剧情 + 发短信 |
| Day 12 | 最终选择日。决定复合还是换乘 |

### 7.6 倒计时仪式感（v3.1 新增）

Day >= 10 且未结束时，Header 区域显示红色脉冲动画标签：

> ⏳ 距离最终选择还有 X 天

Day 10 显示「还有 3 天」，Day 11 显示「还有 2 天」，Day 12 显示「最终选择日」。脉冲动画使用 CSS 关键帧（呼吸闪烁效果），营造终局迫近的紧张感。

### 7.7 下集预告机制（v3.1 新增）

**触发时机**：每天进入下一天时（`proceedToNextDay` 过程中），与次日剧情并发生成。

**实现方式**：
- AI 异步生成约 30 字悬念预告文本，存储在 `GS.nextEpisodePreview`
- 渲染方式：全屏淡入遮罩层（半透明黑色背景 + 白色文字），展示 3.5 秒后自动消失
- 文字格式：用「…」或「？」结尾，引发好奇（例：「一张被撕碎的照片，让所有人陷入沉默…」或「深夜的敲门声，为什么偏偏是他？」）

**容错机制**：
- AI 调用失败或超时时静默跳过，不阻塞游戏流程
- 第二次进入同一时段时不再重复展示

### 7.8 任务卡系统（v3.2 新增）

**触发机制**：
- 触发天数：Day 3–11
- 触发概率：20%（每天独立判定）
- 触发时段：proceedToNextDay() 时检查，非约会日可触发
- 去重：已使用过的任务卡 ID 存入 GS.missionCardUsedIds[]，不会重复出现

**任务卡列表**（从 MISSION_CARDS 常量随机抽取）：

| 任务卡 | 内容 | 特殊提示 |
|--------|------|---------|
| 评价时刻 | 24 小时内不能和某位成员说话 | 当天的所有选项/自由输入/短信都不能选择此人 |
| 升温任务 | 今天必须对某位成员做一件超过平时亲密度的举动 | 自由输入需体现该行为 |
| 沉默考验 | 24 小时内不能主动和任何人说话，只能回应 | 当天的自由输入受限 |
| 关注任务 | 今天必须主动关心某位心情低落的成员 | 自由输入需包含关心对话 |

**UI 展示**：红色任务卡弹窗（showMissionCardModal()），非阻塞，确认后开始执行。到期后自动解除。

**完不成的后果**：无强制惩罚，但完不成的任务会在当天摘要中被 AI 提及——制作组会注意到你没有完成任务。

## 八、约会配对机制

### 8.1 配对方式

| 天数 | 方式 | 说明 |
|------|------|------|
| **Day 4/5/8** | **玩家投骰子** | 弹出骰子弹窗 → 玩家点击投掷 → 6面骰子（1-2→A, 3-4→B, 5-6→C）→ 显示结果 → 玩家确认后 AI 生成配对叙事。选项区只显示「▶ 进入约会场景」。玩家点击 → 自动跳到下午时段 → 生成约会剧情 |
| Day 9 | 强制 X 约会 | 无需骰子，直接生成 X 约会叙事。选项区只显示「▶ 进入约会场景」 |
| Day 10 | 女主指定 | 弹出选择弹窗，玩家从 3 位成员中选 1 位 |

### 8.2 骰子弹窗流程

```
弹出弹窗 → 显示大骰子「?」→ 玩家点击「投骰子」
→ 骰子滚动动画（0.6s）→ 显示点数 + 约会对象
→ 玩家点击「确认，开始约会」→ 结果存入 GS → AI 生成配对叙事
→ 选项区显示「▶ 进入约会场景」
→ 玩家点击 → 自动跳到下午时段 → 生成约会剧情
```

骰子结果存入存档，刷新页面后不会重复弹出。不提供重投按钮——骰子就是命运。

### 8.3 约会对象锁定

骰子投出后 `GS.currentDatingPartner` 存入，当天所有后续 prompt（phase/consequence/freeAction/stay/sms）都注入约会对象提醒：

> ⚠️ 今日约会对象：xxx（已确认，不可更改）。所有涉及约会的叙事必须以 xxx 为对象。

### 8.4 约会场景强制延续

下午 prompt 注入配对叙事中提到的约会场景/地点，强制 AI 延续同一场景，避免「配对说去咖啡厅，下午去了公园」。

### 8.5 小礼物系统

约会后可获得小礼物，增加互动和惊喜感。

**获取时机**：
- Day 4 约会后获得 1 个小礼物
- Day 8 约会后获得 1 个小礼物
- 总共可获得 2 个礼物

**礼物种类**（AI随机生成3选1）：

| 类型 | 示例 | 特殊效果 |
|------|------|---------|
| 手作小物 | 手链、钥匙扣、小挂件 | 送给某成员后，他可能会戴着它出现在后续剧情中 |
| 食物类 | 自制点心、零食、饮料 | 金珉奎、李硕珉收到会额外好感+3 |
| 情感类 | 写有字的纸条、照片、小卡片 | X收到可能触发特殊回忆剧情 |

**送礼机制**：
- 礼物存入 `GS.gifts[]`，Header显示礼物图标（🎁）
- 点击🎁弹出送礼面板，选择礼物+选择送给谁
- 送礼后触发成员的特殊反应剧情（约300字）
- 每个礼物只能送给一个人，送完消失

**成员反应**（根据好感度）：
| 好感度 | 反应示例 |
|--------|---------|
| ≥40 | 反应温暖：「我会好好珍惜的」 |
| ≥60 | 反应亲密：「这是你送的吗……我很开心」 |
| <40 | 反应礼貌：「谢谢，没想到你会送我」 |

**好感度影响**：
- 送礼后好感度 +5
- 如果礼物符合成员喜好（如食物类送给金珉奎），额外 +3
- 未收到礼物的成员 -0~1（如果知道你送了别人）

### 8.6 约会礼物系统（AI 生成礼物池）（v3.2 新增）

**触发时机**：Day 4/5/8 约会配对成功时，AI 按约会地点/场景动态生成礼物池。

**生成方式**：
- scheduler.js 每天检查是否约会日且有未生成礼物
- AI 按约会地点生成 8 个礼物候选，从中抽取 2 个存入 GS.datingGiftPools[]
- 全局去重：GS.datingGiftsUsed[] 记录已使用的礼物 ID，不重复

**礼物获取**：
- 约会后获得 1 个小礼物（从当前池中按序获取）
- 礼物对象含：type（类型）、name（名称）、desc（描述）、fromPartner（约会对象关联）
- 专属标记（isExclusive）：部分礼物仅在特定成员约会时出现

**送礼机制**（同 8.5 小礼物系统一致）：
- 礼物存入 GS.gifts[]，点击 Header 🎁 弹出送礼面板
- 每个礼物只能送给一个人，送完消失
- 送礼后好感度 +5，匹配喜好额外 +3

### 8.7 成员回礼系统（v3.2 新增）

**触发时机**：玩家送礼后，自动调度次日回礼。

**实现方式**：
- game-engine.js 中 scheduleReturnGift(memberId) 存入 GS.pendingReturnGifts[]
- 次日 proceedToNextDay() 时 checkPendingReturnGifts() 检查，弹出回礼弹窗
- 回礼信息存入 GS.returnGiftHistory[] 去重

**回礼内容**：AI 根据送礼对象和好感度生成回礼描述（约 200 字），包含成员的反应。

**好感度影响**：
- 收到回礼：好感度 +2
- 回礼内容随好感度分级：
  - 好感度 < 40：礼貌性回礼，保持距离
  - 好感度 40–59：用心准备的小回礼，带一点个人色彩
  - 好感度 ≥ 60：带有个人情感的特别回礼，可能附手写卡片

## 九、Day 11 真心话环节

### 9.1 基本机制

| 项目 | 内容 |
|------|------|
| 时段 | 🌅 傍晚（真心话）+ 🌙 深夜（醉酒剧情） |
| 问题卡 | 18 张，分三档：轻度（心跳瞬间）6题 / 中度（好感对象）6题 / 深度（放不下的人）6题 |
| 抽取规则 | 每轮从三种难度中各抽1道（共3道），嘉宾依次抽取回答。已抽走的问题不再出现，下一位抽到的不会重复 |
| 轮次 | 4 人轮流抽卡回答，每人 3 轮 = 共 12 次（共消耗12道问题，剩余6道未使用） |
| 选项 | **仅两个**：① 自由输入框（如实回答的内容）② 拒绝回答并喝酒（+1 杯） |
| AI 嘉宾 | 50% 概率选择拒绝回答并喝酒 |
| 选项限制 | Day 11 傍晚**不限制** phaseChoiceCount（真心话 12 轮需要多次选择） |
| 醉酒触发 | 女主+3位成员中，**最先喝到2杯者**判定为醉酒剧情触发者。后续其他人再喝再多也不判断，只触发1位醉酒剧情 |
| 进入下一时段 | Day 11 保留「▶ 进入下一时段」按钮 |

### 9.2 18 道问题卡

**轻度（心跳瞬间）— 6 题**
1. 「今天让你心跳加速的那个人是谁？」
2. 「来这里之后，最让你意外的一件事是什么？」
3. 「如果明天是最后一天，你最想和谁一起吃早餐？」
4. 「你觉得这里有人对你有好感吗？」
5. 「这几天里，最让你印象深刻的一个瞬间是什么？」
6. 「如果可以和某人单独待一天，你会选谁？」

**中度（好感对象）— 6 题**
7. 「你现在心里有感兴趣的人吗？」
8. 「你收到的最让你心动的一条短信是什么？」
9. 「你觉得你和那个人有可能吗？」
10. 「如果那个人今天对你表白，你会怎么回答？」
11. 「这几天有没有某个人的某个举动让你开始在意他？」
12. 「你觉得这里谁最有可能在最后选择你？」

**深度（放不下的人）— 6 题**
13. 「你还想着你的X吗？」
14. 「你和X最后悔的一件事是什么？」
15. 「如果X现在坐在你面前，你最想问他/她什么？」
16. 「你觉得自己是来复合的，还是来换乘的？」
17. 「如果X也在这里，你会怎么面对他/她？」
18. 「你觉得你真的能放下过去吗？」

### 9.3 醉酒剧情（深夜触发）

**女主醉酒后的选项**（选了后弹出选人弹窗，非随机——必须指定某位成员）：
| 选项 | 场景 |
|------|------|
| 被某位嘉宾照顾 | 弹出选人弹窗选择照顾者 → 对方扶你回房间、递水、盖毯子。你酒后卸下防备，说出平时不会说的话 |
| 和某人去阳台吹风 | 弹出选人弹窗选择对象 → 两人去阳台醒酒。冷风让人清醒一半，酒精让话多一倍。深夜的坦诚对话 |
| 留在客厅陪某人 | 弹出选人弹窗选择对象 → 其他人散了，只剩你们俩在昏暗的客厅。沉默比对话更有重量 |
| 和 X 单独对话 | **不弹窗**，直接触发。酒精让伪装失效。X 可能说出分手后没说过的话——后悔、想念、或终于放下的释然 |

**其余 2 位攻略对象醉酒后的选项**：
| 选项 | 场景 |
|------|------|
| 被女主照顾 | 他喝多了，你去照顾他。他酒后卸下防备，说出平时不会说的话 |
| 把女主留在客厅说话 | 他拉住你，不让你走。昏暗客厅里的私密对话 |

**X 醉酒后的选项**（取决于好感度）：
| 好感度 | 触发 |
|--------|------|
| ≥50 | 女主被 X 留住说话 / 女主和 X 去阳台 / **嫉妒剧情**（X 好感 ≥80 且另一成员 ≥50 时触发：X 看到你和别人互动后表现占有欲） |
| <50 | X 自己回房间睡觉，不触发互动 |

### 9.4 社恐反转

女主若选了「社恐小透明」性格，喝酒后暂时不再社恐——话变多、大胆直视、主动靠近。酒醒后在采访间里震惊于自己刚才的表现。

### 9.5 醉酒后隐藏对话

醉酒状态下，角色可能说出平时绝对不会说的话，形成特殊的隐藏对话体验：

**女主醉酒隐藏对话**：
- 可能说出：「其实我一直……算了没什么」「你知道吗，第一天我就注意到你了」
- 对 X 可能说出：「我以为我已经放下了」「你为什么……为什么要来」
- 酒醒后在采访间震惊于自己说了什么，产生后续回味

**成员醉酒隐藏对话**：
- 攻略对象可能说出：「我其实不想和前任复合」「这几天我一直在想你」
- X 可能说出：「我以为我不在乎了」「看到你和别人在一起……我做不到」
- 这些话清醒时绝对不会说，醉酒后才会暴露真心

**触发条件**：
- 醉酒剧情中 AI 有 60% 概率插入隐藏对话
- 隐藏对话内容必须符合角色性格和当前好感度
- 隐藏对话不影响好感度数值，但影响情感氛围

### 9.6 真心话大冒险惩罚版（v3.2 新增）

**与 9.3 醉酒剧情的时序关系**：惩罚作为醉酒剧情的开场设定。AI 在生成深夜醉酒剧情时（详见 9.3），prompt 要求将惩罚内容自然融入剧情发展中（强制执行，无玩家选项）。玩家在看完融入惩罚的剧情后，再选择 9.3 的醉酒互动选项。

**触发条件**：
- Day 11 深夜（phaseIndex === 3）
- 女主当天喝酒 ≥ 2 杯（累计）
- 由 GS.truthPunishment 触发，proceedToNextDay 中清除

**三种惩罚类型**（AI 随机选择一种，强制融入醉酒剧情，无玩家选项）：

| 类型 | 说明 |
|------|------|
| carry（公主抱） | 照顾你的成员必须公主抱你回卧室。体力弱的成员（如李知勋）以其他方式代替 |
| darkroom（强制独处） | 你与随机成员被关进书房强制独处 5 分钟。昏暗灯光下的私密对话 |
| reverse（反问权） | 被指定成员可以反问你一个必须如实回答的问题 |

## 十、短信规则

### 10.1 基本规则

| 规则 | Day 1-7 | Day 8-11 |
|------|---------|----------|
| 可发对象 | 2 位攻略对象（不能发给 X） | 3 位成员（含 X） |
| 短信时间 | 深夜睡前 | 深夜睡前 |
| 短信草稿 | AI 生成 3 条（每条 ≤25 字，简短含蓄） | 同左 |
| 短信内容 | 不直白表白，用暗示和温暖的话语 | 同左 |

### 10.2 短信弹窗（真实手机界面样式）

短信弹窗设计为真实手机聊天界面样式：
- 弹窗整体为手机外壳造型（圆角矩形，带顶部刘海）
- 内部为聊天界面布局：顶部显示「心动短信」标题，下方为消息区域
- 短信草稿以「消息气泡」形式显示（右侧，粉色背景）
- 选择发送对象以「头像+名字」按钮形式显示在底部
- 发送时有动画效果（气泡上移、发送按钮闪烁）

```
┌─────────────────────────────┐
│      ♡ 心动短信             │
├─────────────────────────────┤
│                             │
│   [AI草稿一气泡]            │
│   [AI草稿二气泡]            │
│   [AI草稿三气泡]            │
│                             │
│   或自己写：                 │
│   [自定义输入框]            │
│                             │
├─────────────────────────────┤
│ [成员A头像] [成员B头像] [成员C头像] │
└─────────────────────────────┘

（自定义优先于草稿，两者都填优先自定义，两者都没填不能发送）
```

### 10.3 短信历史回顾

- 专门的短信历史查看功能，可回顾与每位成员的所有短信往来
- 入口：Header 短信图标按钮（📱）点击弹出
- 显示格式：按时间倒序排列，每条显示 Day + 时段 + 发送内容 + 收信者
- 可筛选查看与特定成员的短信记录
- 短信内容存入 `GS.smsHistory[]`，跨天保存

### 10.4 短信后处理

- 短信反应剧情**不生成选项**（深夜收尾）
- 短信后自由输入**计入 stayCount**
- 短信发送后：收信者好感度**直接 +5**（不浮动），未收到短信的成员 **-1**（固定）
- 第二天上午 phase prompt 注入昨晚短信回顾

## 十一、游戏核心循环

### 11.1 时段内循环

```
时段剧情生成（含选项）
  ↓
玩家选择选项 / 自由输入 / 跳过
  ↓
后续剧情生成（含新选项）
  ↓
（可重复，每时段最多 2 次选项选择，含自由输入。Day 11 除外——不限制）
  ↓
选项次数耗尽 → 强制「▶ 进入下一时段」
```

### 11.2 全天循环

```
上午 → 下午 → 傍晚 → 深夜（发短信）
  ↓
短信后：
  ✅ 确认进入下一天（压缩记忆 → 审查面板 → 插图提示词 → Day N+1）
  ✍️ 继续今天（最多 2 次，含自由输入）
```

### 11.3 次数限制

| 限制 | 次数 | 重置时机 | 例外 |
|------|------|----------|------|
| 每时段选项次数 | 2 次（含自由输入） | 进入下一时段 | Day 11 不限制 |
| 深夜继续今天 | 2 次（含自由输入） | 进入下一天 | — |

### 11.4 按钮布局

| 按钮 | 出现条件 | 功能 |
|------|---------|------|
| 🔄 重新生成本段 | 始终 | 重新生成当前段落（保留旧版于 prevRawText） |
| ▶ 跳过并进入下一时段 | 选项未耗尽 | **重新读取至今所有正文 + 女主采访间 + 成员采访间**，生成连贯新剧情并进入下一时段 |

## 十五、采访间系统

### 15.1 女主采访间（🎙）

- 每段至少 1 次，触发即插入（正文→🎙→正文→🎤交替）
- 正文中禁止女主深度自我分析——正文只写即时生理感受（心跳加速、手心出汗、脸颊发烫）
- 所有反思、分析、困惑、自我怀疑、情感复盘必须放在 🎙 标记中
- 过渡句（如「你坐在采访间的椅子上……」）属于 🎙 内容的一部分，不留在正文中
- 正文中不得出现采访间相关描写

### 15.2 成员采访间（🎤）

- **与女主采访间一致**：正文→🎤→正文→🎤交替穿插，触发即插入，至少 1 次
- 正文不直接描写成员内心想法——通过 🎤 呈现
- 过渡句属于 🎤 内容的一部分

### 15.3 X 采访间（🎙️💔）

关键节点必须出现：
- Day 1 读信后
- Day 4 第一批 X 记忆公开后
- Day 9 X 约会后
- Day 12 最终选择前

其他时段可选出现。揭示 X 的内心世界——他在想什么？他还爱女主吗？他为什么来参加节目？

### 15.4 输出结构

```
正文段落1
🎙【采访间】xxx（触发即插入，标记和内容在同一行·过渡句可放在标记内）
正文段落2
🎤【成员名】xxx（触发即插入，标记和内容在同一行·过渡句可放在标记内）
正文段落3
🎙【采访间】xxx
...
🎙️💔【X采访间】xxx（关键节点）
🎬【导演OS】xxx（标记和内容在同一行）
💭【观察员OS】
李龙真：xxx
金叡园：xxx
郑基锡：xxx
特邀嘉宾（成员名）：xxx
【选项】
1. xxx
2. xxx
3. xxx
[好感度: 成员名 +2, 原因: xxx]
```

⚠️ 采访间必须穿插在正文之间，触发即插入，不攒到结尾。导演OS 和观察员OS 放在最后。成员采访间与女主采访间格式一致。

### 15.5 采访间穿插效果规则

**核心原则**：正文动作 → 采访间反应 → 正文后续，形成节奏感和层次感。

**穿插时机**：
- 采访间必须紧跟在相关正文动作之后（不超过2行间隔）
- 正文中出现关键动作、情感转折、重要对话时，立即插入对应采访间
- 不要攒到段落结尾再插入，要穿插在正文中间

**采访间内容要求**：
- 内容简洁（≤50字），不重复正文已描述的内容
- 采访间是对正文动作的内心反应、反思、困惑，不是重复描述
- 女主采访间（🎙）：反思「我为什么要这么做」「我当时在想什么」
- 成员采访间（🎤）：反应「我发现什么」「我注意到什么」「我感觉什么」

**示例**：
```
正文：你拿起桌上的一本书，在上面写了一个字。
🎙【采访间】我当时为什么要这么做我也不知道。
正文：队员拿起书看了一眼上面的字，很吃惊。
🎤【成员名】天呐我发现了什么。
正文：后续剧情继续...
```

**禁止项**：
- 采访间内容与正文重复（正文写了「他很吃惊」，采访间又写「我很吃惊」）
- 采访间滞后插入（正文写了一大段后才插入采访间）
- 采访间内容过长（超过50字）

## 十七、好感度系统

### 16.1 六档层级

| 图标 | 范围 | 含义 |
|------|------|------|
| ❤️🔥 | ≥80 | 深度好感 |
| ❤️ | 60-79 | 明显好感 |
| 💚 | 40-59 | 关注中·有好感 |
| 😐 | 15-39 | 中性·略有好感 |
| 💙 | 0-14 | 中性 |
| 💔 | <0 | 冷淡 |

### 16.2 初始值

| 角色 | 初始好感度 |
|------|-----------|
| X（秘密前任） | 35-50 |
| 攻略对象 | 0-5 |

### 16.3 变化来源

| 来源 | 变化量 | 是否记录日志 |
|------|--------|:--:|
| AI 输出 `[好感度: 成员名 +2, 原因: xxx]` | AI 决定（+1~3） | ✅ |
| 玩家选择选项 | +2~4（选中者）/ **-1（未选中者·固定）** | ✅ |
| 玩家发短信 | **+5（收信者·固定不浮动）** / -1（未收信者·固定） | ✅ |
| 自由输入 | +2~4（指向者）/ -1（未指向者·固定） | ✅ |
| 约会场景（Day 4/5/8/9/10） | **+5（约会对象·额外加成）** | ✅ |
| 真心话环节回答（Day 11） | **+3（回答涉及的对象）** | ✅ |
| 小礼物系统 | **+5~8（收礼者）** / -1（未收礼者·固定） | ✅ |
| 主动降低X好感度 | **-5~10（特定选择可降低X好感度）** | ✅ |

**减值调整说明**：
- 未选中者好感度减值调整为 -0~1（有时不减），减少玩家压力
- 某些选择可以主动降低X好感度（如「明确表示不想复合」「拒绝X的靠近」），让玩家有更多控制权

### 16.4 好感度标记

- AI 每段输出末尾**必须**包含好感度标记：`[好感度: 成员名 +2, 原因: 简述原因]`
- 原因必须**具体可感知**——如「你注意到他抿嘴的动作」「你在他讲冷笑话时笑了」「你主动坐到了他旁边」，禁止写「因为你选择了相关选项」等模糊原因
- 解析器提取后：更新数值 + 写入日志 + **从正文中删除**（不显示）
- 标记放在 `【选项】` 之后，不在正文中

### 16.5 好感度面板

- Header 好感度图标行点击弹出
- 每位成员显示当前好感度 + 最近 **3 条**变化记录（含增减）
- 记录格式：Day X 时段：+2 原因 → 总数值
- 增加用绿色（aff-change-pos），减少用红色（aff-change-neg）

### 16.6 好感度里程碑提示

| 好感度达到 | 提示内容 |
|-----------|---------|
| ≥40 | 弹出提示：「💚 他开始在意你了」 |
| ≥60 | 弹出提示：「❤️ 他明显对你有好感」 |
| ≥80 | 弹出提示：「❤️🔥 他深深被你吸引」 |

提示为非阻塞toast样式，显示2秒后自动消失。每位成员只触发一次，不重复提示。

### 16.7 好感度飘字动画

**触发时机**：调用 `updateAffection()` 且 `delta !== 0` 时创建 `<span class="aff-float">` DOM 元素，从 Header 该成员图标旁飘出。

**队列累积**：100ms 窗口内同一成员的多笔好感度变化 delta 先累加，然后统一飘出（替代原 300ms 防抖），避免多次飘字重叠。

**颜色规则**：
- 正数（+N）：绿色 `#2e7d32`
- 负数（-N）：红色 `#c62828`

**动画效果**：CSS `@keyframes affFloat` — `translateY(-50px)` + `opacity 0→1→0`，持续 1.2s，动画结束后自动移除 DOM 元素。

### 16.8 观察员约束

观察员绝对不能提及具体的好感度数值。评论基于观察到的行为和情感，不是数字。

### 16.9 好感度延迟结算（pendingAffChanges）（v3.2 新增）

**作用**：暂存待处理的好感度变更，由 affect-engine.js 批量结算。

**结算流程**：
- 选项选择后，目标成员好感度变化存入 GS.pendingAffChanges[]
- settlePendingAffChanges() 在合适时机批量处理
- 处理结果写入 affectionLog + 触发飘字动画

**负面行为增强**：
| 行为 | 扣分幅度 |
|------|---------|
| 吃醋/嫉妒表现 | -5 |
| 未收到短信/忽略 | -3 |
| 选项未选中者 | -0~1（有时不减，减少玩家压力） |

### 16.10 好感度行为递减机制（v3.2 新增）

同一行为重复做效果递减：
- 第一次：正常效果（+2~4）
- 第二次：效果减半（+1~2）
- 第三次起：保底 +1，并触发 affFatigue

**记录方式**：GS.affActionHistory[] 存储（memberId, actionType, count），每天不清除，整局有效。

### 16.11 好感度疲劳值（v3.2 新增）

连续对同一人行动效率下降：
- 每连续 2 次对同一成员行动（无其他成员互动穿插），疲劳值 +1
- 结算时好感度增量 = 原始值 - Math.floor(fatigue / 2)
- 与其他成员互动一次即可重置疲劳值（减半）
- 疲劳值上限 5，达到后不再增加

**目的**：鼓励玩家均衡发展多段关系，避免单线冲刺。

| <15 | 选择了独自离开（他放下了） | 选择了独自离开 |

### 17.3 结局回顾

- 最终选择结果（复合成功 / 换乘成功 / 独自离开）

|----------|---------|
| phase | **完整 todayFullText** + 今日已揭示信息 + 昨晚短信回顾 + 待兑现约定 + 时段边界约束 |
| consequence | 采访间摘要 + 今日已揭示信息 + 对话归属提醒 + 纯正文尾部 500 字锚点 + 选项文本 |
| freeAction | 完整原文 + 显式时间锚点（「玩家的行动已执行完毕，当前位置是…」） |
| stay | 完整原文 |
| sms | 完整原文 + 短信内容 |

### 18.4 纯正文尾部锚点

- 过滤 🎬💭🎙🎤🎙️💔 标记行、分隔线、空行、**选项行**（【选项】+ 编号选项）
- 不在引号内切断
- 注入前加当前位置提示

### 18.5 按钮读取范围

「跳过并进入下一时段」和「进入下一时段」在生成 prompt 时，读取范围限定为：

> **正文 + 女主采访间（🎙）+ 成员采访间（🎤）+ X 采访间（🎙️💔）**

**不读取**：导演 OS（🎬）、观察员 OS（💭）。

### 18.6 记忆审查面板（可折叠非模态面板）

跨天压缩后，记忆审查面板渲染在游戏界面顶部（非弹窗），可折叠/展开：

**展开状态**：
```
┌─────────────────────────────────┐
│  📋 Day N 记忆压缩摘要    [−]   │
│  ┌─────────────────────────┐    │
│  │ （可编辑 textarea）      │    │
│  └─────────────────────────┘    │
│  [🔄 重新压缩]  [✅ 确认无误]    │
└─────────────────────────────────┘
```

**折叠状态**：
```
┌─────────────────────────────────┐
│  📋 Day N 摘要待确认...    [+]   │
└─────────────────────────────────┘
```

折叠后可正常操作游戏界面（回顾历史剧情等），确认无误后再展开点击确认。

### 18.7 记忆闪回（flashback）

**触发条件**：
- 好感度突破 80 时，20% 概率触发
- 每位成员每局只触发一次（`GS.flashbackShown[memberId]` 状态：`'pending'` → `true`）

**触发时机**：在 `updateAffection()` 中将好感度达到 80 的成员标记为 `'pending'`，下一段 `generatePhaseNarrative()` 生成时由 AI 注入一段约 200 字的往昔回忆。

**记忆内容**：回忆必须与该成员有关，内容指向二人的甜蜜过往（如初遇那天、某次深夜长谈、一起看过的夜景），以 💭 标记包围显示在剧情中，与当前剧情自然衔接。

**STOP 条件**：该成员闪回状态变为 `true` 后，不再为该成员触发。

## 二十、秘密任务与事件系统

### 20.1 秘密任务系统

**触发机制**：
- 触发天数：Day 2 / Day 5 / Day 7 / Day 10
- 触发时段：仅上午（`phaseIndex === 0`）
- 触发概率：30%
- 前提条件：当天无已激活的秘密任务；非约会日；非强制任务日

**任务列表**：

| 天数 | 任务名 | 目标 | 完成方式 |
|------|--------|------|---------|
| Day 2 | 破冰微笑 | 让某位成员主动对你笑一次 | 自由输入与该成员互动 |
| Day 2 | 职业探秘 | 套出金珉奎的第二职业（不能直问） | 自由输入相关话题 |
| Day 5 | 独处时刻 | 与非X成员单独待在阳台至少5分钟 | 自由输入去阳台 |
| Day 5 | 专注倾听 | 所有自由输入必须包含对尹净汉的关心 | 自由输入带其名字 |
| Day 7 | 寻宝游戏 | 集体外出时找到「蓝色马克杯」并提及 | 自由输入提及物品 |
| Day 7 | 意外助攻 | 让崔胜澈主动为你做一件事 | 自由输入制造契机 |
| Day 10 | 唯一指定 | 短信必须发给文俊辉 | 发短信时选择 |
| Day 10 | 旧伤探询 | 在约会中了解到X最近一个月过得怎么样 | 自由输入相关话题 |

**奖励**：
- 完成：目标成员好感度 **+3**
- 解锁：该成员心动笔记 1 条
- 完成 3 个任务：解锁最终奖励（Day 12 前 X 的未寄出的信）

**UI 展示**：界面顶部出现黄色「📢 制作组秘密任务」通知条（可折叠），含「✅ 我已完成任务」按钮。

### 20.2 嫉妒任务（制作组搞事）

**触发机制**：随机触发，25% 概率。

| 任务类型 | 效果 |
|---------|------|
| 强制晚餐 | 指定成员好感度 +5，其他成员 -2 |
| 禁言令 | 被禁言成员好感度 -3 |
| 短信指定 | 指定成员好感度 +5，被排除成员 -2 |
| 强制约会 | 指定成员好感度 +5，其他成员 -2 |
| 房间交换 | 指定成员好感度 +5，其他成员 -2 |

### 20.3 吃醋事件系统

**触发条件**：当女主与某成员好感度差距 ≥15 时，另一位成员可能触发吃醋。

**效果**：
- 吃醋成员好感度 **-3**
- 被关注成员好感度 **+1**

### 20.4 前任来电/来信（exMessage）

**触发条件**：
- 天数：Day 5–9
- 时段：傍晚或深夜（`phaseIndex ≥ 2`）
- 概率：15%
- 前提：至少一位非X成员好感度 ≥ 20

**效果**：
- 假装没看见：好感度 **-2**
- 安慰他：好感度 **+3**
- 追问详情：好感度 **-5**

### 20.5 午夜匿名电话亭

**触发**：Day 6 深夜（`phaseIndex === 3`）。

**玩法**：
- 选择 3 位成员之一打电话，或选择不打
- 输入电话内容（对方不知道是你）
- 目标成员好感度 **+5**，其他成员 **-2**

### 20.6 匿名提问箱

**触发**：Day 7 傍晚（`phaseIndex === 2`）。

**玩法**：

- 其他成员被抽中时由 AI 决定回答或喝酒

### 20.10 X 幽灵事件（xGhostEvent）（v3.1 新增）

**触发条件**：
- 天数：Day 3–5
- 概率：15%（每天独立判定）
- 每局只触发一次

**效果**：AI 在剧情中浮现一条来自场外 X 的碎片痕迹。痕迹必须模糊、可被忽视，但有心的玩家会察觉到他的存在。三种表现形式（由 AI 选择一种）：
- 未署名字条（被夹在书里、贴在冰箱上）
- 陌生来电（对方不说话或只说了一句模糊的话即挂断）
- 无主物品（一件不属于任何在场者的旧物出现在你房间门口）

**STATE**：`GS.xGhostEvent = { day: number }`，当日结束后在 `proceedToNextDay` 中清除。

**容错**：15% 概率判定失败时不触发，不影响后续剧情。

### 20.11 修罗场强度数值化（rivalryIntensity）（v3.1 新增）

**触发条件**：
- 每次好感度结算后（`settlePendingAffChanges()`），检查是否 ≥ 2 位成员好感度 ≥ 60
- 满足条件则 `rivalryIntensity += 1`

**上限**：5（达到 5 后不再增加）

**级别效果**：

| 强度值 | 效果 |
|--------|------|
| ≥ 1 | 记录到每日历史快照（`affectionHistory`） |
| ≥ 2 | AI 剧情中注入成员暗中较劲描述（「你注意到他看你和别人说话时，手里的酒杯捏紧了」） |
| ≥ 4 | AI 剧情中注入正面冲突/冷战描述（如两人同时邀约、餐桌上针锋相对） |

**数据记录**：`GS.affectionHistory` 每日快照中包含 `rivalryIntensity` 字段，供结局统计图表使用。

### 20.12 心动笔记系统（heartNotes）（v3.2 新增）

**笔记结构**：
```
{ text: string, unlockedAt: { day, source: "affection"|"mission", threshold?, mission? } }
```

**特殊解锁**：完成 3 个秘密任务后，GS.secretMissionUnlockFinal = true，Day 12 前触发 X 未寄出的信。

**UI 展示**：
- Header 📝 按钮弹出心动笔记弹窗（showHeartNotesModal()）
- 弹窗区分来源标签：💚 好感度 / 🎯 秘密任务
- 含进度指示条（当前解锁数 / 总笔记数）

**向后兼容**：旧数据无 source 字段默认 mission。

| `light` | 强制浅色（粉白渐变：`#fce4ec → #f8e8e8 → #fff5f5`） |
| `dark` | 强制深色（暗紫蓝色调，CSS 变量覆盖） |

**实现**：`style.css` 定义约 30 个 CSS 自定义属性，`:root` 为浅色主题，`[data-theme="dark"]` 为深色主题。切换时调用 `document.documentElement.setAttribute('data-theme', theme)`。

**持久化**：偏好存入 `localStorage('svt_theme')`，初始化时自动加载。

**入口**：Header 的 🌙/☀️ 按钮循环切换 auto → dark → light → auto。

### 22.8 打字机速度调节（v3.1 新增）

**GS.typewriterSpeed** 五档设置：

| 值 | 档位 | 行为 |
|----|------|------|
| 0 | 即时 | 跳过逐字逻辑，直接显示完整 HTML |
| 100 | 慢 | 每字约 100ms |
| 50 | 中（默认） | 每字约 50ms |
| 20 | 快 | 每字约 20ms |
| 10 | 极快 | 每字约 10ms |

**入口**：Header 的 `<select>` 下拉框，change 事件更新 `GS.typewriterSpeed` + `saveGame()`。

### 22.9 全屏特效框架（v3.1 新增）

## 二十七、写作风格规范

- 沉浸式恋爱小说+韩综氛围。文艺但不拗口，口语但不随意
- 描写比例：环境~20%、对话~32%、女主心理~15%、肢体细节~20%、成员心理通过采访间和 OS 呈现~13%
- 女主心理精简精准，不过度自我分析。关键时刻留白
- 对话自然口语，符合每个成员人设语气。有潜台词
- 肢体细节：眼神是最重要情感载体。不经意的触碰比刻意更有张力
- 情感浓度递进：Day1-3 克制含蓄 → Day4-7 暗流涌动 → Day8-10 情感爆发 → Day11-12 极致拉扯
- 星座可以作为角色自我认知和轻松话题的参考，但不要变成星座算命节目
- **绝对禁止**：AI 味元叙事、言情小说式夸张比喻、替玩家做情感判断、角色替玩家解读、过度解释、说教式旁白、综艺字幕风对话标注、正文直接描写成员内心、任何抽烟描写、关键词粘合、辈分称谓、韩式敬语后缀

## 三十一、技术注意事项

### 31.1 API 与多模型

- API：DeepSeek API / 硅基流动（SiliconFlow）双提供商
- 默认模型：`deepseek-chat`（DeepSeek V3）
- 可选模型：DeepSeek V3 / DeepSeek V4 / DeepSeek R1 / Qwen / Llama（根据提供商支持）
- API Key 可记忆：`GS.apiKey` + `localStorage('svt_api_key')` 持久化
- temperature：0.85（剧情生成）/ 0.6（下集预告/摘要）
- AI 开关：`GS.aiEnabled` 关闭时使用本地 mock 文本
- 测试模式：`GS.testMode` 跳过所有 AI 调用，使用预设模拟文本
- 连接测试：API 设置面板中支持连接测试（调用一次获取模型列表或简单响应）

### 31.2 AI 一致性校验

- `validateNarrative(rawText, parsed)`：解析后校验格式和人设一致性
- 校验项包括：选项格式、好感度标记存在、采访间交替、禁止词检测
- 校验不通过时生成 corrections 列表，注入下一次 AI 调用的 user message
- correction 反馈累积到 `GS.aiCorrections[]`，不污染原始 userMsg
- 最多 3 次重试，corrections 逐轮追加

### 31.3 选项生成引擎

- 选项由 `option-engine.js`（骨架模块）管理，AI 只写文案，引擎控制格式
- 约会日拦截：只能生成 1 个选项 + 「▶ 进入约会场景」
- 真心话模式：仅 2 个选项（自由输入 + 拒绝喝酒）
- 提问箱模式：如实回答 / 拒绝+喝酒
- 兜底选项：活动词库按时段分（上午/下午/傍晚/深夜），AI 返回空时使用
- 选项文本黑名单：`GS.todayOptionTexts` 每天重置，避免同一玩家重复出现相同的选项模板

### 31.4 基础技术参数

- 解析器：状态机逐行扫描 + 多层兜底
- 降级系统：已移除。AI 失败时 toast 提示刷新重试
- 好感度展示：图标（❤️🔥❤️💚😐💙💔）
- 手机端优化：响应式布局 + 触摸优化
- 所有 AI 生成文本插入 DOM 前必须经过 escHtml() 转义（& < > " '）

### 35.7 核心函数与生成流程

- `generateOneHeartRound(extra)`：主剧情轮生成。`extra` 支持 `isEnding` / `isFreeDeduction` / `isRandom` / `isRegenerate` / `isVisit`。进入「新的一天」时先 `compressOneHeartYesterday()` 将昨日全文压缩为结构化摘要，更新 `oneHeartLastDayStartIdx`（仅压缩新一天内容）。
- 场景一致性校验 `validateOneHeartNarrative()`：校验场景/人物/时段一致性，最多重试 1 次（重试后仍矛盾则记录警告不阻塞）。
- 事件条目提取：从 `parsed.eventItems` 合并进 `oneHeartEventLog`，去重并设 200 条软上限（早期事件合并为单条摘要）。
- Token 配置 `ONE_HEART_TOKEN_CONFIG`：phaseNarrative 4000 / chatReply 1000 / momentGen 800 / diaryGen 1200 / eventStoryGen 1500 / theaterGen 3000。

### 35.8 关系阶段与结局判定

**关系阶段**（由好感度推导 `getOneHeartRelationshipStage`）：

| 阶段 | 好感度区间 |
|------|-----------|
| early（初识） | `< 20` |
| crush（暧昧升温） | `20~39` |
| love（情感冲击） | `40~59` |
| deep（戏剧冲突/高潮） | `>= 60` |

**感情进度阶段**（`updateOneHeartRomanceStage`，由回合数驱动，门控激进/告白类行为）：round<4 初识 / 4~7 暧昧 / 8~11 明确 / >=12 高潮。

**结局判定**（`evaluateEnding()` / `rollEnding()`）：聚合仪表盘不新增独立数值，按以下公式评分：

```
score = clamp(aff - 40, -30, 40)            // 好感 40→0，80→40
       + (brotherStance==='supportive' ? 20
          : consultant ? 8
          : protective ? 4 : 0)             // testing 不加不减
       + (rivalAff > 0 ? -rivalAff*0.5
          : min(10, -rivalAff*0.3))         // 情敌翻车略加分
       - scandal * 5                          // 曝光翻车重罚
       + moodValue * 5                        // 男主情绪基调
```

- 硬触发 BE：`scandal >= 3` 或 `rivalAff >= 50` 或 `aff < 20`
- HE：`score >= 35` 且 `aff >= 60` 且 `brotherStance==='supportive'`
- 否则按 `score` 落 NE / BE

结局分三档（`ONE_HEART_ENDING_TEMPLATES`），`isEnding` 时按档位定调注入 System Prompt：

| 档位 | 标签 | 含义 |
|------|------|------|
| HE | 修成正果 | 曝光可控 + 哥哥祝福 + 情敌未翻车 + 好感达标 |
| NE | 相守于暗 | 未公开也未崩盘，平淡相守 |
| BE | 分道扬镳 | 曝光翻车 / 情敌赢 / 关系失败，任一爆表即触发 |

### 35.9 娱乐圈地下恋专属子系统（IMP-16/17/18）

仅 `worldSetting === 'entertainment'` 启用：

- **行程系统**：`ENT_SCHEDULE_POOL`（7 类偶像本职活动池，共 33 项：录音/舞蹈/综艺/拍摄/粉丝/跨界/行程）经 `generateOneHeartSchedule()` 生成男主/关系户/情敌三人窗口错开行程。
- **探班**：`doVisitMember(roleKey)` 锁定到某成员工作时段生成探班场景；`oneHeartVisitLocked` 同日时间锁（今天时间给了谁就是谁，UI 灰化外函数层兜底）。
- **约会发起门槛**（`initiateOneHeartDate`，由行程条「💞时段」chip 触发）：
  - 普通档（上午/下午/傍晚等空闲档）：需 `好感度 >= 20` 或进入暧昧期（`oneHeartRomanceStage >= 1`）。
  - 翘班约（sneakOut）：需 `好感度 >= 40` 或明确期（`oneHeartRomanceStage >= 2`）。
  - **深夜档单独更高门槛**：需 `好感度 >= 40` 或明确期（`oneHeartRomanceStage >= 2`），UI 显示 `🔒深夜·需好感≥40`，未达标不可点。
  - 上述门槛在 UI 灰化与 `initiateOneHeartDate` 函数层**双重拦截**（避免旧存档直调绕过）。
- **约后禁止同日探班**（修复真 bug）：约会当天 `GS.oneHeartDateToday` 置位，所有探班按钮灰化为 `🔒已约会`；`doVisitMember` 函数层二次兜底，即使 UI 被绕过也拦截并提示「今天已经约过啦」。即「约会」与「探班」同一天互斥，二选一。
- **哥哥考验**：仅「队友的妹妹」设定（关系户 role=`哥哥`）。`updateBrotherStance(delta)` 由 `oneHeartBrotherAff` 单一推导立场四档；中局（`genCount>=15`）哥哥把男主单独叫去「谈谈」试探诚意，强化兄妹信任。
- **情敌事件**：`RIVAL_EVENTS` 事件池，事件卡片选择后 `generateEventStory()` 生成独立短故事（约 150~200 字）。

### 35.10 聊天好感度规则（sendChatMessage）

- 每 **5 条**聊天 +1 好感；每自然日最多 **3 次**加成（对应 15 条）。
- 每日聊天上限 **20 条**，超出提示「今日聊天次数已用完」。
- 上下文窗口 15 条（取最近对话），`chatHistory` 上限 50 条。
- 支持 JSON 污染清洗与复述检测（AI 仅复述用户输入时回退取前一段）。

### 35.11 生日与节日

- `MEMBER_BIRTHDAYS`：13 位成员（含 12 成员 + 全名映射）的公历生日，用于生日特别剧情。
- `HOLIDAYS_1V1`：情人节(2/14)、圣诞节(12/25)、跨年夜(12/31)、新年(1/1)，prompt 注入氛围。

## 三十六、好感度情绪引擎（mood-engine.js）

好感度之外新增**离散情绪状态机**，让 AI 的反应与成员当前心境严格吻合，避免「无理由变脸」。

### 36.1 数据结构

```
GS.mood = { memberId: { state, cause, since, intensity } }
```

- `state`：离散心境，取值见 36.2
- `cause`：情绪原因（让 AI 反应具体不套路）
- `since`：触发时的游戏天数
- `intensity`：程度 1~3

### 36.2 七种离散心境（MOOD_LABELS）

| 状态 | 标签 | 含义 |
|------|------|------|
| calm | 平静 | 默认基线 |
| happy | 开心 | 正向反馈 |
| touched | 心动 | 被触动 |
| jealous | 吃醋 | 看到女主与他人互动 |
| cold | 冷淡 | 负向反馈/被冷落 |
| angry | 生气 | 强烈负向 |
| moved | 感动 | 深层情感触动 |

### 36.3 核心函数

| 函数 | 行为 |
|------|------|
| `setMood(mid, state, cause, intensity)` | 设置情绪。同态时强度累加封顶 3；切换时直接覆盖 |
| `setMoodByEvent(mid, state, cause, intensity)` | 事件触发的情绪设置，额外调用 `syncRivalryFromMood()` |
| `driftMood(mid, state, cause, intensity)` | 漂移：未被选中的在场成员轻微向 jealous/cold 漂移（程度 +1，不覆盖强情绪 angry/cold/intensity>=2） |
| `decayMoodDaily()` | 每日衰减：intensity 每过一天 -1，归零回 calm |
| `syncRivalryFromMood()` | 与修罗场联动：≥2 人处于 jealous/cold/angry 时 `rivalryIntensity + 1`（封顶 5） |
| `updateMoodFromAffChange(mid, delta, reason)` | 由已结算好感变化更新情绪（在 `settlePendingAffChanges` 中逐笔调用）：delta>0→happy，delta<0→cold |
| `buildMoodInstruction()` | 生成 prompt 注入块 |

### 36.4 与修罗场联动

`setMoodByEvent` 与 `updateMoodFromAffChange` 在情绪变化时触发 `syncRivalryFromMood()`：当 ≥2 位成员同时处于 `jealous`/`cold`/`angry`，`rivalryIntensity` 自然升温（与相对好感阈值 `rivalryIntensity` 机制互补）。该值上限 5，用于在 prompt 中递进注入成员暗中较劲 / 正面冲突。

### 36.5 Prompt 注入

`buildMoodInstruction()` 输出 `[INSTRUCTION] 当前心境(强制遵循)` 块，列出每位在场成员的心境与强度（含原因），并约束：

```
规则：reaction 必须与该心境吻合。情绪转变必须有铺垫，禁止无理由变脸。
例：标"吃醋"者本时段应表现出试探/阴阳怪气/刻意靠近，而非突然热络；
    标"冷淡/生气"者不会主动讨好，需后续被哄才缓解。
```

该块在每日剧情生成前注入 User Message，对换乘恋爱与 1v1 模式均生效。

## 三十七、世界观系统（worlds/）

世界观设定从硬编码 prompt 拆分为独立配置模块 `src/worlds/`，目前 `entertainment.js` 实现完整 `WORLD_CONFIG`，其余世界观沿用 `ONE_HEART_WORLDS[].promptSuffix` 描述。

### 37.1 WORLD_CONFIG 结构

以 `entertainment.js` 为例，导出 `WORLD_CONFIG`：

| 字段 | 说明 |
|------|------|
| `id` | 世界观 ID（如 `'entertainment'`） |
| `memberRole` | 男主身份（如「顶流偶像（SEVENTEEN 成员）」） |
| `memberDesc` | 男主世界观设定描述（身份张力、伪装需求等） |
| `secondCareerNote` | 第二职业定位说明（如「音乐制作/编舞/演戏只是个人爱好，核心身份仍是顶流偶像」） |
| `userRoles` | 按女主 `job` 索引的角色描述（11+ 种公开身份各有专属剧情背景） |
| `userFallback` | 未匹配到具体身份时的默认角色描述 |
| `coreTension` | 世界观核心张力（强制遵循，如娱乐圈地下恋的五条核心规则） |

`buildOneHeartSystemPrompt()` 通过 `getWorldConfig(GS.worldSetting)` 取出配置，将 `memberRole`/`memberDesc`/`userRoles[hp.job]` 注入 `[WORLD]` 区块；自定义世界观（`custom`）改用 `GS.oneHeartCustomWorld`。

### 37.2 娱乐圈地下恋专属配置

- **完整 WORLD_CONFIG**：顶流偶像 + 地下恋核心张力（公开克制 / 独处热烈 / 被发现危险感 / 甜蜜代价 / 隐蔽日常场景），强制要求每段剧情体现该张力。

| 综艺 | 综艺录制 / 外景录制 / 电台 DJ / 深夜电台 / 访谈嘉宾 |
