# 娱乐圈模拟器 · 游戏性增强建议

> 参考明星志愿123核心系统，排除属性/竞争者/培训（用户不需要）。  
> 本游戏定位：恋爱为主、事业为辅、无女主数值属性、无竞争者机制。  
> 建议按优先级排序，标注实现复杂度（低/中/高）和预计影响文件数。

---

## 🔴 P0 — 高优先级·高收益·低复杂度

### 1. 奖项/颁奖典礼系统升级
- **现状**：仅有 `_lastAwardDay` 冷却 CD，触发后简单弹 pop 加点人气。
- **建议**：做成年度/季度颁奖典礼事件链（年末 MAMA、金唱片、首尔歌谣等），触发时生成完整典礼剧情（提名→红毯→获奖/陪跑→后台反应），人气波动更大（获奖+15/陪跑-5），增加「年度大赏」大事件感。
- **复杂度**：低 — 复用现有 `AWARD_POOL`，增强剧情生成与结算逻辑。
- **影响文件**：`ent-sim/pools/awards.js`、`ent-sim/engine.js`(结算)、`ent-sim/prompts.js`(注入)

### 2. 金钱/收入系统（简易版）
- **现状**：无金钱概念，所有事业活动只有人气/曝光。
- **建议**：新增 `GS.entSim.money`，出道后每完成工作→+N万韩元，代言/作品发布→+大额。用于约会消费、送礼、粉丝礼物。练习生期无收入靠公司补贴。仅作叙事佐料，不做复杂经营。
- **复杂度**：低 — 新增1个状态字段+各结算处+1。
- **影响文件**：`ent-sim/state.js`、`state.js`(migrate)、`ent-sim/ui.js`(展示)

### 3. 粉丝俱乐部深度展示
- **现状**：`bubble.subscribers` 已存在（100-1000 随机值），但从未在 UI 展示，也未随游戏进程变化。
- **建议**：在事业面板展示粉丝数，出道后人气涨→粉丝+，塌房/绯闻→粉丝-。`bubble.todayCount` 每日重置时与粉丝数联动的互动量。粉丝数到里程碑（1万/5万/10万/50万）弹成就卡片。
- **复杂度**：低 — 在现有 bubble 系统上加 UI + 数值联动。
- **影响文件**：`ent-sim/ui.js`(展示)、`ent-sim/engine.js`(联动)、`ent-sim/state.js`

### 4. 作品销量/音源排名反馈
- **现状**：发布作品仅 `addPopularity(+3)` + `addCareerPublicity`，无差异化反馈。
- **建议**：根据人气和事业曝光度，发布作品后生成随机销量/排名结果（扑街/平平/空降入榜/爆火），不同结果人气加成不同（+2~+12），并生成对应的 dailyBuzz 和粉丝反应文。
- **复杂度**：低 — 在发布作品的结算处加随机 + 二级结果。
- **影响文件**：`ent-sim/ui.js`(发布结算)、`ent-sim/immersion.js`(buzz 生成)

## 🟡 P1 — 中优先级·有收益

### 5. 回归/打歌完整周期机制
- **现状**：有 `COMEBACK_CYCLE_POOL` 和 `MUSIC_SHOW_POOL` 但零散使用。
- **建议**：做成完整的回归周期：预告→音源发布→打歌3周→末放。每阶段自动触发，人气在打歌期每周结算。回归周期中每周有「一位候补」剧情。
- **复杂度**：中 — 需要新增回归状态机。
- **影响文件**：`ent-sim/pools/comeback-cycle.js`、`ent-sim/engine.js`、`ent-sim/cycle.js`

### 6. 公司/经纪人博弈系统
- **现状**：仅有 `经纪警告(曝光过高扣人气)` 一处。
- **建议**：增加公司与女主的博弈层级：
  - 经纪人通知/训话（定期）
  - 公司安排营业CP（被动接受 vs 拒绝后果）
  - 续约/解约选择（合约剩1年时触发）
  - 公司资源分配（推谁、给谁资源，有明争暗斗感但不是属性竞争）
- **复杂度**：中 — 新增事件链 + 合约到期逻辑。
- **影响文件**：`ent-sim/pools/`、`ent-sim/engine.js`、`ent-sim/state.js`

### 7. 狗仔/八卦博弈增强
- **现状**：`DISPATCH_POOL` + `RUMOR_POOL`，曝光≥30 时概率触发。
- **建议**：
  - 玩家可花钱摆平狗仔（花钱消灾）
  - 狗仔跟拍事件：连续几天同一地点出现→曝光风险+3/天
  - "D社元旦爆料"年度事件：年底概率触发，曝光直接+10
  - 公开/私下约会风险差异更大
- **复杂度**：中 — 扩展现有 dispatch 系统。
- **影响文件**：`ent-sim/pools/dispatch-news.js`、`ent-sim/engine.js`

### 8. 女团队友深度互动
- **现状**：`buildEntSimHeroineGroup()` 生成5位姐姐的名字+标签，但仅在 sidebar 展示，无实质互动。
- **建议**：
  - 队友可随机出现在剧情中（宿舍/练习室/待机室）
  - 队友有自己的小剧情线（失恋/家里有事/想退团）→女主可选择帮助
  - 团内气氛值（和谐/紧张）影响营业CP和日常互动
  - 队友发现女主秘密恋爱后的反应（帮忙掩护 vs 劝分手 vs 大嘴巴）
- **复杂度**：中 — 已有 `heroineGroup` 数据，增加事件池和 prompt 注入。
- **影响文件**：`ent-sim/state.js`、`ent-sim/prompts.js`、`ent-sim/pools/`

### 9. 合约系统（练习生→出道→续约）
- **现状**：`contractYears: 7, contractRemaining: 7` 定义但从未使用。
- **建议**：
  - 练习生期末触发「出道最终评价」→出道合约签署
  - 合约剩1年时触发「续约谈判」
  - 合约到期→选择「续约/跳槽/独立发展」→影响结局分支
- **复杂度**：中 — 已有字段，需加事件链和结局分支。
- **影响文件**：`ent-sim/state.js`、`ent-sim/engine.js`、`ent-sim/endings.js`

## 🟢 P2 — 低优先级·锦上添花

### 10. 热搜/趋势操盘（轻度）
- **现状**：`dailyBuzz` 每日自动生成，玩家被动观看。
- **建议**：偶尔让玩家做「公关选择」：正面趋势要推/负面趋势要压（花人气/花掩护次数），选择影响曝光和粉丝数。限1-2次/10天。
- **复杂度**：低 — 已有 dailyBuzz，加交互选项。
- **影响文件**：`ent-sim/ui.js`、`ent-sim/immersion.js`

### 11. 纪念日/回忆录系统 UI 增强
- **现状**：`_romanceMilestones` 记录首次约会/告白/接吻等，但 UI 仅 toast，无回顾页面。
- **建议**：恋情面板加「我们的回忆」时间线，列出所有纪念日及天数倒计时，每30天倍数触发小事件（100天纪念日等）。
- **复杂度**：低 — 已有数据，加 UI 渲染。
- **影响文件**：`ent-sim/ui.js`

### 12. 黑粉/ANTI事件系统化
- **现状**：prompts 中提及但无独立系统。
- **建议**：
  - 人气>20 时概率触发 ANTI 攻击（恶意留言/私生跟踪/编造谣言）
  - 女主回应方式影响人气（冷处理/发律师函/公开回应）
  - ANTI 强度与曝光值正相关
  - 与男主一起应对 ANTI 可以成为感情升温点
- **复杂度**：中 — 新增事件池 + 选项。
- **影响文件**：`ent-sim/pools/`、`ent-sim/prompts.js`

### 13. 生日/节日特殊事件
- **现状**：`birthdayInfo()` 已检测四人组生日，但仅在 prompt 中提示「今天是XX的生日」。
- **建议**：
  - 女主生日：收到男主/哥哥/队友的惊喜（+好感+人气）
  - 男主生日：专属约会机会，送礼物有好感加成
  - 情敌生日：情敌可能借机请女主帮忙选礼物→吃醋事件
  - 节日（情人节/白色情人节/圣诞节）：专属剧情线
- **复杂度**：低 — 已有检测，加事件生成。
- **影响文件**：`ent-sim/state.js`、`ent-sim/prompts.js`、`ent-sim/pools/calendar-events.js`

### 14. 更丰富的约会地点
- **现状**：`initiateEntSimDate` 取 venue 参数。
- **建议**：增加更多约会地点类型，每种有不同风险/好感加成：汉江公园(低风险+2)、深夜小吃摊(中风险+3)、弘大街头(高风险+4)、私人影院(高风险+5)、对方宿舍(极高风险+6)。
- **复杂度**：低 — 已有 venue 参数，扩展可选列表。
- **影响文件**：`ent-sim/engine.js`、`ent-sim/data.js`

### 15. 练习生期训练选项
- **现状**：练习生期的日程自动推送（训练/月评/出道组筛选），玩家只能被动推进。
- **建议**：每天让玩家选择当日训练重点（声乐/舞蹈/体能/自修），不同选择触发不同小剧情，对出道评价有微弱影响。
- **复杂度**：中 — 练习生期已有 phase 系统，加每日选择。
- **影响文件**：`ent-sim/engine.js`、`ent-sim/ui.js`、`ent-sim/prompts.js`

### 16. 电台/直播/综艺出场
- **现状**：综艺和画报通过事件池触发，但无「电台」「直播」类型。
- **建议**：
  - VLIVE/Weverse 直播：女主单人直播 + 随机队友/男主乱入
  - 电台节目：午夜电台谈心→粉丝留言互动→可能出现暧昧提问
  - 打歌待机室：竞演团队互动、前后辈打招呼
- **复杂度**：低 — 扩展事件池。
- **影响文件**：`ent-sim/pools/`、`ent-sim/prompts.js`

### 17. 组合活动与个人活动的冲突
- **现状**：日程自动安排。
- **建议**：偶尔出现「团活儿 vs 个人约会」的时间冲突，女主需选择。选约会→团内气氛-，选团活儿→男主失落但理解。制造职业与恋爱的冲突感。
- **复杂度**：低 — 日程冲突事件。
- **影响文件**：`ent-sim/cycle.js`、`ent-sim/prompts.js`

### 18. 粉丝来信系统增强
- **现状**：有 `FAN_LETTER_POOL` 随机来信。
- **建议**：粉丝来信内容与近期行为关联（发布作品后→好评信、塌房后→脱粉信、谈恋爱嫌疑被拍到→"欧尼在谈恋爱吗"质问信），增加代入感。
- **复杂度**：低 — 已有系统，加条件分支。
- **影响文件**：`ent-sim/pools/fan-letter.js`

### 19. 音乐银行/打歌节目排名
- **现状**：有 `MUSIC_SHOW_POOL` 但触发后仅有简单剧情。
- **建议**：完整打歌流程 → 每周五公布排名 → 候补→一位与否→安可舞台→后台庆祝/失落。与作品热度联动。
- **复杂度**：中 — 扩展音乐节目池 + 排名计算。
- **影响文件**：`ent-sim/pools/music-show.js`、`ent-sim/engine.js`

### 20. SEVENTEEN 13人团完整出场
- **现状**：`_svtTodaySeen` 防止同一天重复出场，`TEAMMATE_FLAVOR` 提供队友风味文本。
- **建议**：13人更均匀地在日常中轮换出场。不只是男主和情敌，其他队友也可以和女主有简单互动（前辈照顾/后辈仰慕/一起练舞/被开CP玩笑），增加团魂感和真实感。
- **复杂度**：中 — 扩展现有队友出场系统。
- **影响文件**：`ent-sim/pools/teammate-flavor.js`、`ent-sim/prompts.js`

### 21. 结局细分与结局CG
- **现状**：结局判定在 `endings.js`，按 tier + careerLevel + depth 组合。
- **建议**：
  - 按公开/地下 × HE/NE/BE × 事业等级 细分更多结局文本
  - 结局时展示「感情线回顾 + 事业线回顾」双时间线
  - 增加结局后记（N年后文字结局）
- **复杂度**：中 — 扩展结局矩阵 + UI。
- **影响文件**：`ent-sim/endings.js`、`ent-sim/ui.js`

### 22. 存档槽/加速模式
- **现状**：单一存档，无加速。
- **建议**：支持多存档槽（3个），允许玩家平行尝试不同路线。练习生期提供「跳至出道」选项（手动推进训练20天太长）。
- **复杂度**：高 — 存档系统重构。
- **影响文件**：`state.js`、`ui-renderer.js`

## 设计原则
1. **不增加女主数值属性** — 不引入歌艺/演技/口才等需要训练成长的属性系统。
2. **不增加竞争者系统** — 唯一的竞争者是团内情敌，不扩展更多竞争对手。
3. **恋爱为主、事业为辅** — 所有增强服务于"地下恋爱+娱乐圈背景"的核心体验。
4. **事件驱动而非数值驱动** — 用事件/剧情/选择而非数值面板呈现进展。
5. **与现有代码架构兼容** — 复用 `engine.js` 的 side effects 系统、`pools/` 的事件池机制、`immersion.js` 的 buzz 生成。
