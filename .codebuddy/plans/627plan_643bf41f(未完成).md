## 项目背景

基于 `6月24日待修清单.md` 和 `待修改项_详细展开.md` 的审计结果，对 SEVENTEEN 项目进行第二轮修复。

## 已修复项（不再重复）

1. 好感度显示混乱
2. 采访间衔接断裂
3. Day 3 跳转无剧情
4. 选项多样性不足

## 待修复项（54 项）

覆盖以下模块：

- **Prompt 与剧情规则**：读信字数、短信采访间/保密/深夜禁发、私密体质专属、压缩记忆去对话归属、普通选项字数、系统标记防泄漏。
- **系统配置**：API 提供商重构、生日取代星座、季节/日期/天气/节日系统。
- **日程与任务**：Day 3 说故事重复、约会日日程调整、去掉随机约会、约会骰子结果写入、保留约会状态。
- **好感度与互动**：严格丢弃好感度标记、延迟结算、难度提升、选项风险扣分、队内修罗场。
- **X 记忆物品**：X 档案中显示物品、按需生成 2 个 + 50 容量缓存池。
- **午夜电话亭**：即时生成 + 正文不注入、记录按钮。
- **UI 与交互**：选项/自由输入次数拆分、保存意图清空、礼物已改造标签、送礼缺女主人设。
- **新增功能**：匿名提问箱固定按钮/取消卡死/动作描写/喝酒分支、剧情导出、Day 8 修罗场、深夜去掉选项、Day 9 双向读信、约会地点池、短信草稿动态、Day 11 真心话重构、测试模式、Day 12 铺垫。

## 约束

- 保持 `var`、字符串 `+` 拼接风格
- 不引入新依赖
- 所有 AI 文本插入 DOM 前必须 `escHtml()`
- 使用 `showToast()` / `showConfirmModal()` 替代 `alert()` / `confirm()`
- 新增状态字段必须在 `defaultGameState()` 和 `migrateSave()` 中兜底
- 最小化、聚焦修改，避免无关重构

## 技术栈

- 语言：JavaScript (ES Modules)
- 构建：Vite 5.4
- 状态：本地 `localStorage` + 全局 `GS` 对象
- API：DeepSeek（扩展硅基流动/千问）
- UI：Vanilla JS + CSS 变量

## 实现策略

按"状态/数据 -> Prompt -> 引擎 -> 好感度 -> UI -> 测试导出"的顺序分批实施，每个批次内部先改底层字段，再改调用方，最后补样式和测试。所有修改需满足向后兼容，旧存档通过 `migrateSave()` 自动升级。

## 详细修复清单

### 1. Prompt 与剧情规则（src/prompts.js、src/memory.js、src/x-archive.js）

- Day 1 傍晚读信字数 `300-500` -> `~200`
- Day 1 傍晚读信 prompt 由 7 步枚举改为 2-3 句概括
- 短信剧情加入 `女主采访间 / 成员采访间 / 导演OS / 观察员OS` 格式，字数 `~1000` -> `~500`
- 追加短信内容保密规则：仅收发双方知道内容，其他人只能观察表情
- 私密体质专属：全局规则、`buildHeroineProfilePrompt()`、`buildUserMessage` 三处声明禁止投射到成员
- 深夜时段正文中禁止女主实际发送短信，只可想/犹豫
- 普通选项 consequence 字数 `~1500` -> `~1000`
- 系统注入标记 `## ` -> `[SYSTEM]`/`[INSTRUCTION]`，末尾追加防泄漏指令
- 压缩记忆 `src/memory.js` 删除"保留对话归属"要求
- `src/x-archive.js` 物品 prompt 保持「名称/样式/故事」格式

### 2. 系统配置与数据层（src/state.js、src/data.js、src/api.js、src/formatters.js）

- `state.js` 新增：
- `apiProvider`、`apiModel`

- `formatters.js` 补齐 Day 3 各时段 `getMandatoryTask()` 描述

### 3. 游戏引擎流程（src/game-engine.js）

- 开局随机生成季节、月份、起始日期；`goToNextDay()` 推进 `gameDay`
- `proceedToNextDay()` 中基于季节和前一天天气生成新天气，检查节日/生日
- `goToNextDay()` 后 `window.scrollTo(0, 0)`
- `resetPhaseState()` 保留 `currentDatingPartner` 和 `pendingDatingResult`
- 约会骰子动画结束后立即写入 `GS.pendingDatingResult`
- 新增 `flushPendingAffection()`，在生成新剧情前结算 `pendingAffChanges`
- 匿名提问箱：固定按钮、取消不卡死、动作描写、喝酒分支特殊剧情
- 午夜电话亭：即时生成约 100 字反应，弹窗内展示
- Day 8 约会修罗场：30% 概率 + 选中好感最低成员时弹出维持/换人选项
- Day 9 双向读信：prompt 注入双向读信指令
- Day 11 真心话重构：抽卡 + 50% 自动判定 + 女主回合输入框 + 12 轮
- Day 12 铺垫：上午先生成约 500 字铺垫剧情，再弹出最终选择
- 测试模式：读取本地 mock 文件

### 4. 好感度与互动系统（src/parser.js、src/affection.js、src/skeleton/affection-engine.js）

- `parser.js` 解析 `[好感度: ...]` 时推入 `GS.pendingAffChanges`，不立即写入

- AI 调用仅在用户操作或明确触发时发生，避免冗余请求

- 所有 DOM 操作复用现有渲染路径，新增字段通过 `Object.assign` 更新 `GS`

- 预期成果：输出关键文件索引、依赖关系摘要、待修复点精确位置（行号/函数名），作为每轮修改前的依据
