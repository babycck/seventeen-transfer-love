## 用户需求

针对项目两套记忆系统（换乘恋爱三层记忆 + 1v1 事件流记忆）提出全面优化方案。经代码分析和用户确认，识别出 6 个核心问题需要修复，覆盖两种游戏模式。

## 产品概述

优化两种游戏模式的 AI 记忆系统，解决跨天失忆、压缩信息低效、历史无限膨胀、剧情重复检测缺失、衍生物（日记/信箱/朋友圈）反复嚼旧记忆等问题。核心改善方向：1v1 模式补全跨天摘要压缩机制、压缩输出结构化、换乘恋爱历史分层衰减注入、新增重复检测校验、事件日志存储衰减与去重、衍生物生成增加去重注入与校验。

## 核心功能

- 1v1 模式新一天时压缩昨日全文为结构化摘要，注入最近 3 天记忆
- 每日压缩从自由文本改为 JSON 结构化输出（事件/台词/约定/揭示信息分类）
- 换乘恋爱 dailySummaries 按时间距离分层衰减注入（近期完整/中期精简/远期只留约定）
- 新增剧情重复检测：新生成剧情与近期摘要做关键词重叠检查，超阈值返回 correction
- 1v1 事件日志存储软上限 200 条，超限时自动合并最早条目为"早期摘要"
- 事件日志新增指纹去重（前8字+后8字），存储和注入双重去重
- 衍生物去重：日记去重参考扩充到最近 4 篇全文；信箱注入最近 5 条历史消息；朋友圈去重补 reply 文本扩充到 5 条

## Tech Stack

- 语言：JavaScript (ES Modules)，Node.js 18+
- 框架：Vanilla JS + Vite
- AI API：DeepSeek (`deepseek-chat` model)
- 状态管理：`GS` 全局对象 + `localStorage` 持久化
- 约束：`var` 而非 `let/const`；字符串拼接用 `+`；不引入新依赖；`escHtml()` 转义；旧存档向后兼容

## Implementation Approach

### 核心策略

分 6 个独立优化点，按依赖关系排序实施。所有改动基于现有 `memory.js` / `state.js` / `prompts.js` / `parser.js` 架构，不引入新模块文件。

### 关键技术决策

1. **1v1 跨天摘要复用 `compressTodayToSummary` 而非新建函数**：该函数已存在于 `memory.js:150`，只需在 1v1 的"新一天"触发点调用它，结果存入 `GS.oneHeartYesterdaySummary` 和新增的 `GS.oneHeartDailySummaries` 数组（最近 3 天注入）

2. **结构化压缩输出**：修改 `compressTodayToSummary` 的 system prompt，要求 AI 输出 JSON `{"events":[],"dialogues":[],"promises":[],"revealedInfo":[]}`。解析失败时 fallback 到原文截取。注入时按类别分别标注

3. **分层衰减注入**：在 `prompts.js:283-288` 换乘恋爱历史注入处改造循环逻辑——最近 2 天完整、3-5 天前截取前 200 字、6+ 天前只保留结构化数据中的 `promises` 和 `revealedInfo`

4. **重复检测放在 `parser.js:validateOneHeartNarrative` 和 `validator.js:validateNarrative`**：提取新 narrative 的关键词（中文 >=2 字的连续片段），与最近 3 天摘要文本做 Jaccard 相似度，超 40% 返回 correction。维护约 20 个 STOP_WORDS 过滤常见词

5. **事件日志衰减 + 去重**：在 `game-engine.js:1786-1790` concat 后先调用 `dedupeEventLog` 全量去重，再检查 200 条软上限。超限时把前 100 条合并为一条 `"[早期事件] " + items.slice(0,100).join('；')`，保留后 100 条明细

6. **衍生物去重注入**：日记去重参考从 2 篇前 60 字扩充到 4 篇前 150 字；信箱 `generateMessage` 注入最近 5 条历史消息 + 生成后 Jaccard 校验；朋友圈去重参考补 reply 文本扩充到 5 条；事件日志注入前调用 `dedupeEventLog` 过滤

### Performance & Reliability

- 压缩调用复用现有 `TOKEN_CONFIG.dailySummary`（3000 tokens），不增加配额
- 1v1 跨天压缩在新一天加载时异步执行，try/catch 包裹失败时 fallback 截取尾部 1000 字
- 结构化 JSON 解析失败时 fallback 到 `full.slice(0, 1000)`，与现有兜底一致
- 重复检测的关键词提取复杂度 O(n)，单次 <1ms
- `oneHeartDailySummaries` 数组限制 7 条（7 天），超限时 shift 最早一条
- 衍生物去重校验阈值（0.5）高于剧情重复检测（0.4），因为衍生物篇幅短话题集中
- 旧存档兼容：`migrateSave` 中所有新字段都有 undefined 兜底

### 各文件修改详情

**`src/memory.js`**

- 修改 `compressTodayToSummary()`（line 150-172）：system prompt 改为要求 JSON 输出 `{"events":[],"dialogues":[],"promises":[],"revealedInfo":[]}`；解析 AI 返回时 `JSON.parse` 失败 try `match(/\{[\s\S]*\}/)` 再 parse，仍失败 fallback `full.slice(0, 1000)`
- 新增 `export async function compressOneHeartYesterday()`：从 `GS.oneHeartLastDayStartIdx` 到 `GS.todayFullText.length` 截取昨日剧情段，调用压缩逻辑，结果存入 `GS.oneHeartYesterdaySummary`，push 到 `GS.oneHeartDailySummaries`（限 7 条超限 shift），更新 `GS.oneHeartLastDayStartIdx`
- 新增 `export function dedupeEventLog(arr)`：对事件条目按"前8字+后8字"指纹去重，保留首次出现的条目

**`src/state.js`**

- `defaultGameState()` 新增 `oneHeartDailySummaries: []`
- `migrateSave()` 新增 `if (!Array.isArray(GS.oneHeartDailySummaries)) GS.oneHeartDailySummaries = [];`

**`src/prompts.js`**

- 1v1 模式（line ~1007 `oneHeartEventLog` 注入之后）：注入 `GS.oneHeartYesterdaySummary` 和 `GS.oneHeartDailySummaries` 最近 3 天，结构化数据按 events/dialogues/promises/revealedInfo 分类标注
- 换乘恋爱（line 283-288 改造）：最近 2 天完整摘要、3-5 天前截取前 200 字、6+ 天前若 JSON 则只注入 promises + revealedInfo 否则跳过
- 日记去重（line 1284-1288）：从 `slice(-2)` 前 60 字扩充到 `slice(-4)` 前 150 字，含 heroineEntry + memberEntry
- 朋友圈去重（line 1255-1261）：从只列 post 改为 `post + reply`，扩充到最近 5 条
- 事件日志注入前去重（line 1001, 1213, 1273 三处）：`slice(-N)` 后调用 `dedupeEventLog` 过滤

**`src/game-engine.js`**

- 1v1 "新的一天"触发处（line ~2310，`GS.pendingChoiceText = '📅 新的一天'` 之后）：调用 `await compressOneHeartYesterday()`，try/catch 包裹失败静默跳过
- eventLog 衰减（line 1786-1790 之后）：concat 后先 `dedupeEventLog` 全量去重，再检查 `length > 200`，超限合并前 100 条为摘要

**`src/modals/message-modal.js`**

**`src/parser.js`**

- `validateOneHeartNarrative`（line 523+）末尾增加重复检测：提取新 narrative 关键词 `match(/[\u4e00-\u9fa5]{2,}/g)`，过滤 STOP_WORDS，与最近 3 天 `GS.oneHeartDailySummaries` 文本做 Jaccard 相似度，> 0.4 返回 correction。新一天场景跳过检测

**`src/validator.js`**

- `validateNarrative`（line 12+）增加类似逻辑：提取 narrative blocks 的 content 拼接，与最近 3 天 `GS.dailySummaries` 做 Jaccard 相似度检测，超 40% 返回 correction

## Implementation Notes

- **1v1 跨天压缩不阻塞 UI**：`compressOneHeartYesterday` 在 `generateOneHeartRound` 之前 await，但 try/catch 包裹失败时 fallback 截取尾部 1000 字
- **结构化数据向后兼容**：旧 `dailySummaries` 条目是 plain text，新条目是 JSON string。注入时先 `try JSON.parse`，失败则当 plain text 处理
- **重复检测防误判**：新一天场景跳过检测（早晨场景天然与前一天有重叠元素）。Jaccard 用 Set 交集/并集计算
- **衍生物去重防误杀**：日记/朋友圈/信箱的去重校验阈值（0.5）高于剧情重复检测（0.4），重试只做 1 次避免无限循环
- **事件日志指纹去重**：用"前8字+后8字"而非全文 hash，因为 AI 提取的 eventItems 可能有微小措辞差异但实质相同
- **与好感度修复计划无冲突**：本计划修改的 prompts.js 区域（line 283-288 和 1007 附近）与好感度修复计划修改的区域（line 967, 1091, 1172）不重叠
