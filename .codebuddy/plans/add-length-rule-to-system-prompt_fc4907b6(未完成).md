## 需求概述

用户反映 AI 生成的剧情篇幅仍然过短，上次修复（统一 prompts.js 中各场景类型的字数指令）效果不理想。用户要求只修改 system prompt，在其中加入字数强制规则，不调整 maxTokens。

## 核心需求

在换乘恋爱模式的 system prompt（`buildSystemPrompt()`）中，于 `## RULE ## 全局写作规则` 块末尾新增一条字数强制规则，参照 1v1 模式已有的 `[长度强制]` 写法，明确不同场景类型（phase/consequence/freeAction/stay）的字数下限，增强约束力。

## 修改范围

仅修改 `src/prompts.js` 文件中的 `buildSystemPrompt()` 函数。

## 技术方案

### 实现方法

在 `buildSystemPrompt()` 函数的 `## RULE ## 全局写作规则` 块（当前第 191-209 行，规则 1-15）末尾，追加一条规则 16，内容为字数强制规则。

### 规则内容设计

参考 1v1 模式第 981 行的 `[长度强制]` 写法，结合换乘恋爱模式的不同场景类型，规则内容为：

```
16. [长度强制] 每段剧情必须达到以下字数（硬性要求，禁止输出过短段落）：
    - 新时段剧情（phase）：1500-2000 字（约等于 1500-2000 个汉字）
    - 选项后续剧情（consequence）：800-1000 字
    - 自由输入扩写（freeAction）：1200-1800 字
    - 继续今天（stay）：1000-1500 字
    如果内容偏短，必须扩展环境描写、对话、心理活动和肢体细节，直到满足字数。
    JSON 格式开销不计入字数，仅计算 blocks 中 content 字段的正文汉字数。
```

### 关键设计决策

1. **放在 system prompt 而非 user message**：system prompt 对 AI 的约束力更强，尤其 DeepSeek 等模型更重视 system prompt 中的"规则"类指令。user message 中的字数指令作为辅助不删除，形成双重约束。
2. **参照 1v1 模式写法**：1v1 模式已有的规则格式（`[长度强制]` + `硬性要求` 措辞）已被验证有效，复用相同模式确保风格一致。
3. **区分场景类型**：不同场景类型需要的字数不同（phase 最长 1500-2000字，consequence 最短 800-1000字），避免一刀切。同时与 user message 中的字数要求保持一致。
4. **不调整 maxTokens**：满足用户要求，仅靠 prompt 层面的字数约束来提升生成长度。

### 需要注意的点

- 当前规则编号 1-15（第 191-209 行），新规则为 16（紧接规则 15 之后）
- 不要删除 user message 中已有的字数指令，保留作为双重约束
- 保持与现有代码风格一致（`var`、字符串拼接 `+`）
- system prompt 的规则部分 AI 重视度高，措辞要明确有力
