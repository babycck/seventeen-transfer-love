## 用户需求

在 1v1「只为你心动」娱乐圈世界观下，行程条顶部一直显示「当前 8:00（上午）」的时钟卡死不动，导致时间门控（过期探班锁定、可约时段过滤）完全失效。用户要求恢复确定性时间推进，让时钟随剧情真正走动。

## 产品概述

将 1v1 娱乐圈模式的 24 小时时钟从「依赖 AI 声明、经常卡在 8 点」改为「代码确定性推进」：每生成一段新剧情，当天时段索引 +1 并映射到一个真实时钟值（上午→中午→下午→傍晚→深夜）；探班/约会时按目标成员的时段吸附时钟。顶部时钟文字、过期探班「时间已过」、可约 chip 的「过去时段」过滤随之实时生效。

## 核心特性

- 每生成一段新剧情，时钟按固定日程表确定性前进，不再卡在 8 点
- 时钟与 AI 显式声明时段对齐（AI 声明更晚时段时向上吸附，绝不回退）
- 探班/约会按成员工作时段吸附时钟，且整体单调不回退
- 过期探班（当前时间越过成员时段终点）真正锁定并显示「时间已过」，函数层与 UI 双层拦截
- 可约时段 chips 的「过去时段」过滤随真实时钟正确隐藏
- 仅影响 1v1 娱乐圈世界观，transfer 模式与其他 1v1 世界观完全不受影响

## 技术栈

- 语言/运行时：JavaScript (ES Modules)，Node.js 18+，Vanilla JS + Vite（与现有项目一致）
- 仅修改既有模块：`src/state.js`、`src/utils.js`、`src/game-engine.js`、`src/ui-renderer.js`

## 实现方案

### 总体策略

用「当天回合计数器」驱动确定性时钟推进，替代原来「仅当 AI 声明 sceneTime 才推进」的失效逻辑。新增每日起始归零的 `oneHeartRoundsToday`，每生成一段新剧情（非重生成/非结局/非 noTimeAdvance 的侧边动作）计数 +1，映射到一个日程表 `[8,12,16,20,22]`（上午/中午/下午/傍晚/深夜）。时钟值取「确定性时钟、上一幕时钟、AI 声明时段起点」三者最大值，保证单调不回退且与 AI 声明对齐。探班/约会显式吸附到目标时段（同样用 max 不回退）。

### 关键决策与权衡

1. **新增 `oneHeartRoundsToday` 而非复用 `oneHeartDaySegment`**：原 `oneHeartDaySegment` 注释声称「段驱动」但游戏进行中从未递增，是死代码且默认语义为 0（首段即中午，与「首日入口不显示中午」的设计意图冲突）。新增字段语义清晰、初始化/迁移/重置点明确，改动 blast radius 更小、不易误伤旧存档。
2. **确定性为基、AI 声明为向上吸附**：彻底消除「AI 不声明→卡 8 点」的根因；同时保留 AI 显式声明更晚时段时向上吸附，满足用户「与 AI 声明逻辑对齐」诉求，且 prompt 注入的「时钟 X时」随之变为真实值，AI 写出的场景自然同步。
3. **单调不回退（max 钳制）**：探班/约会会把时钟推到该成员时段（可能晚于当前确定性值），随后生成自由剧情时若确定性时钟回退，用 max 与上一幕时钟比较，避免时间倒流导致过期判断错乱。
4. **约会调用补 `noTimeAdvance`**：`initiateOneHeartDate` 当前未带 `noTimeAdvance`，会与回合计数推进冲突；改为显式吸附所选 slot 的时段起点并传 `noTimeAdvance:true`，时钟控制权集中。

### 性能与可靠性

- 全部为 O(1) 的整数映射与 `Math.max`/`indexOf` 判断，无性能影响。
- 不改动 render 逻辑（`renderOneHeartScheduleStrip` 已读取 `GS.oneHeartDayClock`），时钟变化后由既有 `window.__renderAll()` 触发重渲染，`_expired` 与 `_isPast` 自然生效。
- 迁移兜底：旧存档无 `oneHeartRoundsToday` 时默认 0，首次新剧情即正常推进，无破坏性。

## 实现注意

- 沿用 `var` 声明与字符串拼接风格，不新增日志/依赖，避免日志刷屏。
- `doVisitMember` 与 `initiateOneHeartDate` 在 `saveGame()` 前后设置时钟，确保 `renderAll` 读到最新值。
- 不改动顶部时钟文字模板本身（仅其背后的 `oneHeartDayClock` 变为真实值）；「探班=偷会，时间锁」说明文字保留。
- `state.js` 中 `oneHeartDayClock`/`oneHeartDaySegment` 的旧注释需同步修订，说明 `oneHeartDaySegment` 已废弃、时钟改由 `oneHeartRoundsToday` 驱动。

## 架构设计

时钟推进链（仅 1v1 娱乐圈生效，外部调用 `if (GS.gameMode==='oneHeart' && GS.worldSetting==='entertainment')` 隔离）：

```mermaid
flowchart TD
  A[generateOneHeartRound 新剧情] --> B{isRegenerate/isEnding/noTimeAdvance?}
  B -- 否 --> C[oneHeartRoundsToday+1]
  C --> D[_detClock = SCHEDULE[idx]]
  D --> E[_newClock = max(_detClock, 上一幕时钟)]
  E --> F{AI 声明合法更晚时段?}
  F -- 是 --> G[_newClock = max(声明起点, _newClock)]
  F -- 否 --> H[保持 _newClock]
  G --> I[写 oneHeartDayClock / oneHeartTimeOfDay]
  H --> I
  B -- 是 --> J[保持当前时钟]
  K[doVisitMember / initiateOneHeartDate] --> L[时钟 = max(当前, 成员时段起点)]
  L --> I
  I --> M[renderAll → 行程条顶部时钟/过期/可约过滤生效]
```

// utils.js —— 当天段索引 → 24 小时时钟映射（确定性推进基准）
export var ONE_HEART_DAY_CLOCK_SCHEDULE = [8, 12, 16, 20, 22]; // 段0..4 → 上午/中午/下午/傍晚/深夜

// game-engine.js 时间块核心逻辑（伪代码，替换 line 2514-2546 内 AI 声明段）
if (!extra.isRegenerate && !extra.isEnding && !extra.noTimeAdvance) {
  GS.oneHeartRoundsToday = (GS.oneHeartRoundsToday || 0) + 1;
  var _idx = Math.min(GS.oneHeartRoundsToday - 1, ONE_HEART_DAY_CLOCK_SCHEDULE.length - 1);
  var _prevClock = (typeof GS.oneHeartDayClock === 'number') ? GS.oneHeartDayClock : 8;
  var _detClock = ONE_HEART_DAY_CLOCK_SCHEDULE[_idx];
  var _newClock = Math.max(_detClock, _prevClock); // 确定性推进，但不早于已推进的时钟（约会/探班吸附）
  var _declared = (parsed && parsed.sceneTime) || (parsed && parsed.sceneContext && parsed.sceneContext.timeOfDay) || '';
  if (['凌晨','清晨','上午','下午','傍晚','深夜'].indexOf(_declared) >= 0) {
    _newClock = Math.max(getOneHeartPeriodStartHour(_declared), _newClock); // 与 AI 声明对齐，向上吸附
  }
  GS.oneHeartDayClock = _newClock;
  GS.oneHeartTimeOfDay = getOneHeartTimePeriod(_newClock);
}
