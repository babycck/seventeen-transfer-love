## 产品概述

综合修复 entSim（娱乐圈模拟器）9 个 bug：UI 绑定失效、AI 自创韩文名、营业后场景串台、告白进度太快、关系网无反馈且可无限点、时段感弱、告白可重复点、JSON 截断解析失败、人气变动不可见。

## 核心功能

- 开新作品按钮和命名弹窗中的类型/备选名按钮可正常点击
- AI 不再自创韩文名或韩文台词，女主称呼严格使用注入的中文艺名
- 营业/事件后选项承接当前场景，不跳转到无关场景
- 告白需 depth>=4 且不可重复触发；晚档约会两次才 +1 depth
- 关系网节点显示亲密度和立场数值；每日限 3 次主动互动
- 营业/随机事件/关系网互动/作品推进不消耗时段，仅主线选项和自由输入推进时段
- JSON 截断时正则提取已完成的 narrative 和 options，减少重试覆盖
- 人气每次变动写入 careerHistory 并附带原因；UI 人气行可点击查看变动日志

## Tech Stack

- 纯 JavaScript (ES Modules)，复用现有 entSim 架构
- `var` + 字符串拼接代码风格（遵循 AGENTS.md 约定）
- 不引入新依赖，所有功能用浏览器原生 API

## 实现方案

### Bug 1：开新作品点击无反应

**根因**：`ui.js:366` `bind(sel, fn)` 内部用 `document.getElementById(sel.replace('#',''))`，传入 `.es-work-type` 时点号没去掉，永远找不到 class 元素。`onWork()`（:506）和 `promptWorkTitle()`（:533）均受影响。
**修复**：在 ui.js 新增 `bindClass(sel, fn)` 辅助函数，封装 `document.querySelectorAll(sel).forEach`。将 `onWork` 和 `promptWorkTitle` 中的 `bind('.class', fn)` 替换为 `bindClass`。

### Bug 2：AI 自创韩文名/韩文台词

**根因**：`prompts.js:26` 注入了艺名但约束不够强，AI 见女主是「韩国女艺人」就自创「심예」。
**修复**：在 `buildEntSimSystemPrompt()` 称呼规则后追加显式禁令。

### Bug 3：营业后选项场景串台

**根因**：choice 的 user message 只有「玩家选择了选项：xxx」+ 通用状态快照，丢了「正在营业直播」的事件上下文。
**修复**：在 `buildEntSimUserMessage` 的 choice 分支中，从 `GS._entSimCurrent` 取上一段 narrative 摘要（前 150 字）+ type 标签，注入场景连续性指引。

### Bug 4+7：告白进度太快 + 告白可重复点

**根因**：`tryConfession` 仅查 `depth>=3`，3 次约会即达 threshold；未查 `confessionDone`。
**修复**：depth 门槛 3→4，追加 `!confessionDone` 门控；约会降速（dateCount 每 2 次才 +1）。

### Bug 5：关系网点击无变化且可无限点

**根因**：NPC 节点不显示数值；`interactNpc` 无次数限制。
**修复**：UI 显示亲密度/立场；每日限 3 次；advanceWorld 重置次数。

### Bug 6：时段感弱

**根因**：`generateEntSimRound` 无条件调 `advanceTimeSlot()`，每次操作都推进时段。
**修复**：仅 phase/choice/free 推进时段；`triggerEntSimEvent` 扩展 advanceTime 参数；晚档传 advanceTime:true。

### Bug 8：JSON 截断解析失败

**根因**：`parseEntSimResponse` 在 safeParseJson 失败后无正则提取；`repairJson` 的 lastBrace 截断在截断 JSON 上行为不正确。
**修复**：正则提取兜底 + repairJson 深度检查 + maxTokens 3200→4000。

### Bug 9：人气变动不可见

**根因**：`addPopularity(delta)` 只改数值不写 careerHistory；5 个调用点均不传 reason；UI 人气行只显示数值不可点击；`public-opinion.js:111-115` 有重复 careerHistory push。
**修复**：`addPopularity(delta, reason)` 加 reason 参数写 careerHistory；更新 5 个调用点传 reason；删 public-opinion.js 重复 push；UI 人气行改可点击按钮弹出日志面板。

## 实现要点

- Bug 3：`GS._entSimCurrent` 在 `buildEntSimUserMessage` 调用时仍持有上一轮数据，可安全读取
- Bug 4：`dateCount` 和 `npcInteractionUsed` 需在 `initEntSimState` 和 `migrateSave` 两处兜底
- Bug 6：`triggerEntSimEvent` 扩展签名需向后兼容——opts 可选，不传时 advanceTime 默认 false
- Bug 8：正则提取只在 JSON 解析全链路失败后触发，不影响正常路径性能（O(n) 单次扫描）
- Bug 9：`addPopularity` 加 reason 参数需向后兼容——reason 可选，不传时行为不变
- Bug 9：`public-opinion.js:111-115` 删去重复 push 后，applyDiscoveryBlowback 仍正常记录（由 addPopularity 内部写入 type='popularity' 条目）
