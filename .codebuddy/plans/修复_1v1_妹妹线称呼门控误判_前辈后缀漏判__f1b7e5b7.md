## 用户需求

用户在 1v1「只为你心动」模式（队友的妹妹 + 心动小屋设定）初识期（romanceStage<1）下，推进剧情时控制台反复出现警告：`[1v1] 重试后仍有校验矛盾，采用重试结果： [称呼门控] 队友的妹妹设定下初识期须称男主"全圆佑前辈"，禁止直呼名字。请补上"前辈"。`

用户期望：修复校验误判，使 AI 合规写出的正确称呼「全圆佑前辈」（名字后紧跟「前辈」）不再被门控判为违规，从而消除「重试后仍有校验矛盾」的死循环。

## 核心问题

- `src/validator.js` 的 `checkOneHeartAddressing()` 在妹妹线初识期检测直呼男主名时，合法豁免条件不完整：只豁免了「名字前带前辈」（`_before` 含前辈）和「名字后带欧巴」（`_after` 含欧巴），却未豁免「名字后带前辈」（`_after` 含前辈）。
- 妹妹线的正确称呼形式是「全圆佑前辈」，「前辈」作为后缀位于名字之后。AI 合规输出时 `_after` 含「前辈」但代码未检查，`_before` 又不含「前辈」，导致误判为直呼名字违规。
- AI 按修正提示重试仍写出「全圆佑前辈」，被同一规则再次驳回，形成反复矛盾；game-engine.js 二次校验只 warn 不阻塞，最终采用仍被判违规的重试结果。

## 修复目标

- 让正确称呼「全圆佑前辈」通过校验，不再触发「校验矛盾」警告与无效重试。
- 保留对真正直呼名字（如「全圆佑。」「全圆佑说」无前后缀）的拦截与重试。
- 不影响 romanceStage>=1（欧巴已解锁）路径、不影响非妹妹设定、不影响 transfer 模式。

## 技术栈

- 语言/运行时：JavaScript (ES Modules)，Node.js 18+，Vanilla JS + Vite（与现有项目一致）
- 仅涉及单文件修改：`src/validator.js`

## 实现方案

### 总体策略

`checkOneHeartAddressing` 是一处「基于内容的代码硬兜底」门控，逻辑集中在 `src/validator.js:63-89`。本次为最小改动：仅修正初识期直呼名字判定的豁免条件，使其同时接受「名字后紧跟前辈」这一合规形式。

### Bug 定位与修复

当前 `src/validator.js:76-86`：

```js
if (memberName && (GS.oneHeartRomanceStage || 0) < 1) {
  var _idx = content.indexOf(memberName);
  while (_idx >= 0) {
    var _before = content.substring(Math.max(0, _idx - 3), _idx);
    var _after = content.substring(_idx + memberName.length, _idx + memberName.length + 3);
    if (_before.indexOf('前辈') < 0 && _after.indexOf('欧巴') < 0) {   // 漏判：未豁免「名字后紧跟前辈」
      corrections.push('[称呼门控] 队友的妹妹设定下初识期须称男主"' + memberName + '前辈"，禁止直呼名字。请补上"前辈"。');
      break;
    }
    _idx = content.indexOf(memberName, _idx + 1);
  }
}
```

根因：妹妹线合规写法是「全圆佑前辈」，即「前辈」在名字之后。判定条件只检查了 `_before.indexOf('前辈')`（名字前）与 `_after.indexOf('欧巴')`（名字后欧巴），未检查 `_after.indexOf('前辈')`。当文本为「全圆佑前辈」时，`_before`（名字前3字）不含「前辈」、`_after` 含「前辈」却不被检测 → 条件为真 → 误判违规。

修复（一行）：

```js
    if (_before.indexOf('前辈') < 0 && _after.indexOf('前辈') < 0 && _after.indexOf('欧巴') < 0) {
```

语义：名字出现时，仅当其前不含「前辈」、其后不含「前辈」、其后也不含「欧巴」时，才算直呼名字违规。这样既正确放行「全圆佑前辈」，又保留对真正直呼名字（如「全圆佑。」「全圆佑说」）的拦截。

### 影响面分析（避免回归）

- 本块仅在 `(GS.oneHeartRomanceStage || 0) < 1` 进入，romanceStage>=1（欧巴解锁）路径不执行，与 prompt 层 `getOneHeartAddressRule()`（prompts.js:977-991）的初识期只称「前辈」、暧昧期改口「欧巴」规则一致。
- 函数首行 `if (GS.gameMode !== 'oneHeart' || !isSisterSetting()) return corrections;` 已将 1v1 外与妹妹设定外的场景完全隔离，transfer 模式及非妹妹 1v1 不受影响。
- 改动仅一行条件拼接，无新增依赖、无 API/行为面变化，符合 AGENTS.md 的「最小、聚焦改动」约定。
