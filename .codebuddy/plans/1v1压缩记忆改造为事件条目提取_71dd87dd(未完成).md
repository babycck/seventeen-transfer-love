## 用户需求

将 1v1「只为你心动」模式现有的压缩记忆系统（每10回合调用 AI 生成约1000字整段摘要）替换为「事件条目提取」机制：每次压缩触发时，AI 从剧情中提取关键事件，每个事件用一句话概括，包含人物、地点、事件要素。

- 短事件示例：「女主给正主买咖啡」
- 长事件示例：「正主在练习室生病了，女主照顾他，被哥哥怀疑，哥哥让队友金珉奎送正主回宿舍」

## 产品概述

1v1 模式的 AI 上下文记忆从「整段文字摘要」升级为「结构化事件条目列表」。事件条目更短、更精准、token 消耗大幅降低（预计减少约 80%），AI 能更清晰地理解历史发生的关键事件而非模糊的摘要叙述。

## 核心功能

- 在现有压缩触发点（每15回合+10段未压缩剧情），将 AI 调用从「生成1000字摘要」改为「提取事件条目列表」
- 事件条目以纯文本一句话形式存储，按时间顺序排列
- 所有 1v1 prompt 注入点改为读取事件条目列表，格式化为 `- 事件1\n- 事件2` 的列表注入
- 回顾弹窗中 1v1 的「压缩记忆」标签页改为「事件回顾」，以列表形式展示事件条目
- 换乘恋爱（经典模式）完全不受影响
- 当日即时上下文（未压缩近期剧情注入、尾部 tail 衔接）保留不动

## Tech Stack

- 语言: JavaScript (ES Modules)，使用 var 不用 let/const，字符串用 + 拼接
- 运行时: Node.js 18+ / 浏览器原生 API
- AI API: DeepSeek (deepseek-chat)
- 无新增依赖

## Implementation Approach

### 核心策略

在现有 1v1 异步压缩触发机制（game-engine.js:1863-1911）的基础上，仅替换 AI 调用的 system prompt 和存储目标，不改变触发条件、指针管理、原文缓存等逻辑。

### 关键技术决策

1. **新建独立字段 `oneHeartEventLog`**：不复用 `dailySummaries`（换乘恋爱共用字段），避免格式混淆。1v1 的 prompt 注入点和回顾弹窗改为读取新字段，换乘恋爱的 `dailySummaries` 读写路径完全不动。

2. **提取方式：复用现有压缩 AI 调用**：不额外增加 AI 调用次数。在同一次异步调用中，将 system prompt 从「压缩为1000字摘要」改为「提取事件条目列表」，AI 输出换行分隔的事件文本，前端按 `\n` split 解析。

3. **输出 token 限制降低**：从 `TOKEN_CONFIG.dailySummary`（3000）降到 `ONE_HEART_TOKEN_CONFIG.eventExtract`（1000），事件条目远比摘要短。

4. **当日即时上下文保留不动**：`prompts.js:1001-1008` 的未压缩近期剧情注入（`oneHeartLastCompressedIdx` 之后的 todayFullText，截断3000字）是同批次内衔接用的，不属于跨批次压缩记忆，保持不变。

5. **向后兼容**：旧 1v1 存档中已有 `dailySummaries` 条目保留在数据中不删除，回顾弹窗做 fallback 显示（`oneHeartEventLog` 为空时显示旧摘要）。

### 性能分析

- **Token 节省**：旧方案每次压缩生成约1000字摘要 × 3批 = 3000字注入；新方案每次压缩生成约10-20条事件 × 3批 = 30-60条短句（约500-1000字），减少约 70-80% 注入 token。
- **AI 调用次数不变**：复用现有异步压缩调用，不新增调用。
- **输出 token 限制降低**：从 3000 降到 1000，AI 生成更快。
- **无阻塞**：保持现有异步非阻塞架构。

## Implementation Notes

- `GS` 引用不可替换，使用 `GS.oneHeartEventLog.push(...)` 而非重新赋值
- `parseEventItems` 解析需容错：AI 可能返回带编号前缀（`1. xxx`）或带 `-` 前缀的文本，需 strip 前缀后取正文；空行过滤
- 回顾弹窗中 1v1 事件条目为只读列表展示（不像旧摘要那样可编辑 textarea），因为事件条目是结构化短文本，编辑意义不大
- `oneHeartArchivedNarratives`（原文缓存）保留不动，导出功能不受影响
- `oneHeartPromiseLog` 的 `createdAtRound` 调整逻辑保留不动，因为触发机制不变

## Architecture Design

### 数据流（1v1 事件提取）

```
剧情生成完成 (game-engine.js:1864)
  → oneHeartGenCount++ 
  → 检查触发条件 (>=15 && 未压缩>=10)
  → 取10条 todayFullText 原文
  → 原文缓存到 oneHeartArchivedNarratives (不变)
  → AI 调用: system="事件提取助手", user=10条原文
  → AI 返回: 换行分隔的事件文本
  → parseEventItems() 解析为事件数组
  → push 到 GS.oneHeartEventLog
  → 更新 oneHeartLastCompressedIdx / oneHeartGenCount -= 10
```

### 注入流（1v1 prompt 构建）

```
buildOneHeartUserMessage (prompts.js)
  → type==='phase': 读取 oneHeartEventLog → 格式化为 "- 事件1\n- 事件2..."
  → type==='chat': 同上（事件短，无需 slice）
  → type==='theater'(diary): 同上
```
