## 用户需求

用户反馈每个时段开始时，虽然 AI 会生成剧情文本，但**第一个选项（选项 A）的文本总是雷同**——无论当前的剧情场景/对话/氛围是什么，第一个选项都是类似的通用模板（如"主动搭话""保持距离""沉默不语"等），没有基于当前时段的实际剧情内容来生成有区别、有情境感的选项文字。

用户期望：选项文本应该"读取剧情"——即每个选项（尤其是第一个选项）必须从当前时段刚刚写出的剧情文本中**具体推导**，而不是独立于剧情生成的通用套路。

## 核心要求

- 增强 `prompts.js` 中对 AI 的选项生成指令，要求选项必须**基于刚生成的剧情文本推导**
- 专门约束**第一个选项**不能是通用模板
- 在 phase 和 consequence 两种类型中都强化此约束
- 保持现有代码风格（使用 `var`，不使用模板字符串等）

## 技术方案

### 修改目标

**唯一修改文件**：`src/prompts.js`

### 修改点 1：增强 `noRepeatNote`（第 597-599 行）

当前内容：

```javascript
var noRepeatNote = '...\n' +
  '⚠️ 选项必须严格基于当前场景和在场人物，避免出现与当前上下文无关的互动选项。避免重复使用"主动搭话""保持距离""沉默不语"等通用模板，每个选项指向不同的行动方向。';
```

增强为：

```javascript
var noRepeatNote = '...\n' +
  '⚠️ 选项必须严格基于你刚刚写出的剧情文本中的具体场景、对话、细节来推导，每个选项要像「从剧情中长出来」的一样自然。\n' +
  '⚠️ 第一个选项（选项A）尤其必须直接从本段剧情的核心场景/冲突/氛围中提取行动方向，绝对禁止使用"主动搭话""保持距离""沉默不语"等独立于剧情的通用模板。\n' +
  '⚠️ 三个选项指向完全不同的行动方向，禁止出现语义重复的选项。';
```

### 修改点 2：增强 Phase 类型生成指令（第 637-638 行）

当前：

```
'必须包含：... + options 数组（3个，每个含 affName/affDelta/affReason）。\n'
```

改为：

```
'必须包含：... + options 数组（3个，每个含 affName/affDelta/affReason）。\n' +
'⚠️ 在写 blocks 之前先构思选项：选项必须是你即将写出的剧情文本的自然延伸——每个选项对应一个在该情境下合理的行动方向。选项A必须直接回应当前叙事的核心情境。\n'
```

### 修改点 3：增强 Consequence 类型生成指令（第 602-604 行）

当前：

```
'请生成后续剧情（~500字 JSON），必须包含...选项。\n'
```

改为：

```
'请生成后续剧情（~500字 JSON），必须包含...选项。\n' +
'⚠️ 选项必须基于刚刚生成的后续剧情来推导，禁止使用与剧情无关的通用选项模板。\n'
```

### 设计理由

1. **最小改动**：只修改 `prompts.js` 中的 prompt 文本，不修改任何逻辑代码，不影响现有功能
2. **对症下药**：问题本质是 prompt 约束不够强，AI 偷懒使用通用模板；增强约束后 AI 会生成更差异化的选项
3. **三个层面约束**：noRepeatNote（全局规则） + phase指令（时段剧情） + consequence指令（后续剧情），覆盖所有选项生成场景
4. **无副作用**：纯 prompt 修改，不涉及状态/逻辑/渲染变更，无回归风险

### 实施注意事项

- 保持现有代码风格：`var` 声明，`+` 字符串拼接，不使用模板字符串
- 新增的提示文本使用中文，与现有风格一致
- 不修改其他文件（`game-engine.js`/`store.js`/`state.js` 等均无需改动）
