## 用户需求

女主选择「队友的妹妹」身份（1v1 模式 + 娱乐圈世界观 + 关系户=亲哥哥，role==='哥哥'），她比全团 13 名成员都小，按身份逻辑理应对成员称「前辈」或对男主称「欧巴」，但当前游戏让女主对成员直呼名字，与身份设定矛盾。

## 产品概述

修正称呼控制逻辑，使「队友的妹妹」身份下的女主默认称成员「前辈」、与男主亲密时可自然称「欧巴」，禁止直呼名字；同时保持其他模式、其他身份、其他世界观的称呼规则完全不变。

## 核心功能

- 妹妹设定下，女主对全体成员默认使用「前辈」称呼（圈外晚辈对全员年长者的礼貌称谓）
- 与男主感情升温后可自然称「欧巴」（年下女对年上男的亲密称呼，不卡通用规则的好感>60 门槛）
- 妹妹设定下禁止女主对成员直呼名字（她不是队友，无多年随意关系）
- 亲哥哥仍可用「我哥」/名字（现有亲哥豁免保留）
- 校验器（validator）放行「前辈/欧巴」，不再将其判为违规
- 渲染层不再把正文中的「前辈/后辈」硬删除
- 换乘恋爱模式、其他 userRoles、其他世界观：称呼行为完全不受影响

## 技术栈

Vanilla JS (ES Modules) + Vite，复用现有 prompt 构建、称呼校验、渲染后处理逻辑，不引入新依赖、不新增状态字段。

## 根因分析

当前代码存在三处互相对立的规则，导致妹妹身份下 AI 被迫直呼名字、且正确称呼被系统拦截/删除：

1. `src/prompts.js:1119` 1v1 全局写作规则强制「直呼名字」；`src/prompts.js:1026` 哥哥段仅允许「直呼名字或好感度高称欧巴」，无「前辈」选项。
2. `src/validator.js:217-219` 全局绝对禁止「前辈/后辈」文本；`validator.js:260/314` 女主称呼违规文案强制「欧巴或直呼名字」，把前辈判违规。
3. `src/ui/narrative-box.js:10` 渲染前硬禁词处理 `text.replace(/前辈/g,'').replace(/后辈/g,'')` —— 即便 AI 生成正确「前辈」也会被从正文删除。
4. `src/worlds/entertainment.js:14` 人设已写明「你比团里十三个人都小」，但没有任何调用点把该身份应有的称呼注入 prompt 或放行校验。

## 实现方案

### 身份判定 Helper（共享）

在 `src/utils.js` 新增并导出 `isSisterSetting()`，集中判定「队友的妹妹」设定，供 prompt/validator/render 三处复用，避免逻辑分散：

```js
export function isSisterSetting() {
  return GS.gameMode === 'oneHeart' && GS.worldSetting === 'entertainment'
    && GS.oneHeartRelationCharacter && GS.oneHeartRelationCharacter.role === '哥哥';
}
```

（role==='哥哥' 即「队友的妹妹」人设，见 `ui-renderer.js:2432` 注释、`state.js:38` default、`worlds/entertainment.js:14`）

### 逐文件修改

1. **src/prompts.js**

- 行 1119 全局写作规则：当 `isSisterSetting()` 为真时，将「称呼规则：直呼名字。好感度高时可称"欧巴"。」替换为「称呼规则：你是队友的妹妹，比全员都小，对成员默认称"前辈"，与男主亲密时可称"欧巴"，禁止直呼名字。」
- 行 1026 哥哥角色称呼段：在「你称呼男主...」规则后追加妹妹专属说明——「作为队友的妹妹，你对男主及所有成员默认称"前辈"，亲密时称"欧巴"，禁止直呼名字」（保留亲哥「我哥」/名字豁免）。

2. **src/validator.js**（函数 `checkAddressViolation`，全局调用，1v1 亦走此校验）

- 行 217-219 全局「前辈/后辈」禁令：加 `isSisterSetting()` 分支——妹妹设定下不把「前辈/后辈」判为违规。
- 行 260 女主称「哥」违规文案：妹妹设定下「应称"欧巴"或"前辈"」而非「直呼名字」。
- 行 314 汇总 correction 文案：妹妹设定下同步改为「女主应称"前辈"或"欧巴"；禁止直呼名字；禁止"-xi"」。

3. **src/ui/narrative-box.js**

- 行 10 `sanitizeHardWords`：删「前辈/后辈」前判断 `isSisterSetting()`，为真则跳过该替换，使正文「前辈」得以保留。

### 性能与可靠性

- `isSisterSetting()` 为纯同步布尔判断（仅读 GS 字段），开销可忽略；不影响每次生成的耗时。
- prompt 注入仅在 1v1+娱乐圈+哥哥 时多一段短文本，token 增量极小。
- 改动零新增依赖、零新增状态字段，完全符合 AGENTS.md「make minimal, focused changes」。

### 影响范围（防回归）

- 仅 `isSisterSetting()` 为真（1v1 + 娱乐圈 + 队友的妹妹）时改变称呼行为；其余所有分支（换乘恋爱、1v1 其他身份、其他世界观）逻辑不变。
- 不改团内相处规则（`prompts.js:1084/1086` 描写的是成员互称，保留不动）、不动经典模式 `formatters.js getAddressRules`（仅经典模式 `buildSystemPrompt` 使用，1v1 不走）。
- 保留亲哥「我哥」/名字豁免，不破坏既有哥哥设定表现。

## 实现备注

- 保持现有 `var` 风格与字符串 `+` 拼接约定，不引入模板字符串。
- `isSisterSetting` 在 `utils.js` 导出后，于 prompts.js / validator.js / narrative-box.js 顶部 import 引入（narrative-box.js 现从 `core.js` 导入，可改为/追加从 `utils.js` 导入）。
- 修改后 `npm run build` 验证打包通过；本地 `npm run dev` 进 1v1 娱乐圈 队友的妹妹，确认 AI 生成文本女主称成员「前辈」、对男主「欧巴」、不再直呼名字，validator 不再报「前辈」违规，正文「前辈」不被删；切换换乘恋爱/其他身份确认不受影响。
