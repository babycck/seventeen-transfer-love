## 产品概述

修复并增强《换乘恋爱 × SEVENTEEN》娱乐圈模拟器（entSim 模式）。在修复当前运行时崩溃、存档数据一致性、剧情生成时段/状态门控等问题的同时，新增一个**无 AI 测试模式**：固定角色、透明展示池子数据与 AI 扩写边界，让玩家可以在前几天反复测试而不消耗 token。

## 核心问题

1. 生产构建运行时崩溃：`pickBuzzComments is not defined`
2. 点击「避风头」按钮后立即生成剧情，行为不符预期
3. 存档数据错乱：人气崩溃、时间线错位、职业身份不一致、女团队友数量异常、秘密条目重复、日记计数不一致、bubble 订阅数与人气倒挂
4. 看不到日记：手机 App 入口读取 `_diaryEntries` 数据缺失/格式错误，与独立弹窗双入口不同步
5. 出道日/出道后事件池门控缺失：出道当天仍可能触发练习生期事件（公司审核、月末评价），已出道剧情未锚定出道当天核心场景
6. 章节池与通用池混入高阶日程：第一章池含「年末新人舞台」「颁奖礼」「红毯试装」等，`COMMON_POOL` 含出道后专属内容且无门控
7. 低好感度下越级暧昧：好感度 5 即生成「同款衣角」「红毯回头图」「恋情曝光」等高暧昧/高曝光剧情
8. 曝光惩罚数值过严：单次 -7 可让人气从个位数掉到 1，后续玩法基本锁死

## 新增测试模式需求

1. 控制台开关：`window.__toggleTestMode()`（已存在，需增强）
2. 开启后跳过 DeepSeek 调用，使用本地池子数据生成剧情
3. **固定角色**：

- 男主 = 全圆佑（Wonwoo）
- 哥哥 = 李硕珉（DK / Dokyeom）
- 情敌 = 尹净汉（Jeonghan）

4. 将三人成员数据（catchphrases、comforts、食物禁忌、性格标签、关系标签）注入剧情上下文
5. 剧情模板透明化：

- 显示天气、日期、阶段、固定角色行程
- 直接展示抽中的池子条目及来源字段
- 对 AI 本应扩写的部分标注「该部分由 AI 驱使」
- 标注加载了池子的哪些数据、会扩写什么方向

6. 数值/副作用按池子条目 `delta`/`effects` 直接应用
7. 聊天/朋友圈/theater 等返回轻量 mock 文本并标注测试模式

## Implementation Approach

采用「最小改动 + 门控补齐 + 数据兜底 + 测试模式增强」的策略：

### 1. 运行时错误修复

在 `src/ent-sim/ui.js` 本地补定义 `pickBuzzComments(item, count)`，从 `HOT_SEARCH_REPLY_POOL` 中按热搜标题关键词匹配抽取 1-3 条评论；无匹配时返回通用兜底评论。

### 2. 避风头行为修正

确认 `goEntSimNextDay` 只推进天数、降低热度、生成次日报到提示，不直接生成主剧情。当前 `ui.js:1084-1092` 点击后调用 `goEntSimNextDay().then(rerender)`，若 rerender 触发了 pending 剧情，则在 `goEntSimNextDay` 返回前清空 `GS._entSimPendingEvent`，或在 UI 层为 hidingout 设置跳过标记。

### 3. 日记双入口同步

手机 App 的 `renderDiaryInnerFS()` 改为直接消费 `E.diary` 与 `E.diaryHis`（与独立弹窗一致）；同时补齐 `_diaryEntries` 写入逻辑，确保每条含 `day`/`text`/`timestamp`。在 `engine.js` 写 diary 时三处同步写入。

### 4. 存档数据一致性

在 `src/ent-sim/state.js` 迁移/初始化路径中：

- 统一 `bubble.subscribers = clamp(50 + popularity * 12, 0, 99999)`，并随 popularity 变化同步刷新
- 修复 `secret.items` 追加前先去重（按文本相似度/包含关系）
- 修正 `_diaryCounter` 与 `diary.length` 保持一致
- 触发出道/职业转换时同步 `GS.heroineProfile.profession = E.career.profession`
- 女团队友数不足 5 人时重新生成
- 时间线异常时重置 `_gameDayCount` 与 `debutDay` 的相对关系

### 5. 日程池时段门控

- 给 `ent-schedules.js` 中 `CHAPTER1_NOVICE` / `CHAPTER2_SPROUTING` / `COMMON_POOL` 等条目补充 `require: 'chapter>=N'` / `require: 'debut'` / `require: 'traineePhase>=2'` 等
- 修复 `cycle.js:85`：当 `filterByRequire(phasePool, E)` 为空时，fallback 不应回到 `TRAINEE_EARLY_POOL`，而应降级到同阶段通用池或提示补池
- `COMMON_POOL` 中出道后专属条目加 `require: 'debut'`

### 6. 出道日锚点

- 调整 `engine.js` 中 `rollDailyAgenda()` 与出道判定/晋升的调用顺序：先判定是否今日出道，若触发出道则强制替换 agenda 为出道专属日程
- 出道当天优先从 `MILESTONE_DEBUT` / 出道专属子池抽取
- 出道判定后立即 `saveGame()`

### 7. 低好感度门控与曝光惩罚

- 给 `TRAINEE_ROMANCE_POOL` 加 `minAff`/`maxAff`，好感度 < 10 时只允许被动/观察类事件
- 男主/情敌浪漫日程与剧情按 `affection` / `romanceStage` 过滤
- 曝光事件增加 `affection >= 15 && scandalHeat >= 3` 门控
- 曝光惩罚改为阶梯式并设下限：`popularity = max(3, popularity - penalty)`，避免锁死

### 8. 测试模式增强

在现有 `src/ent-sim/test-mode.js` 基础上增强：

- 新增 `TEST_FIXED_ROLES` 常量：男主 wonwoo、哥哥 dk、情敌 jeonghan
- 在 `initEntSimState` 中检测到 `window.__ENT_SIM_TEST` 时强制覆盖 maleLead/brother/suitor
- `buildTestNarrative` 输出结构：
- 头部：【测试模式】Day X · 上午 · 晴
- 阶段与角色：章节 / 人气 / 男主全圆佑 / 哥哥李硕珉 / 情敌尹净汉
- 今日日程：main / related / rival / maleLead / brother（直接展示 agenda 字段）
- 池子素材：列出本次加载的池子条目及来源池名
- AI 扩写区：标注「该部分由 AI 驱使」，说明 AI 会扩写的内容方向
- 固定选项 2-3 个，按好感度分段
- `runEntSimType` 的 chat/moment/theater 路径返回带「【测试模式 · AI 扩写区】」标注的 mock 文本

## Implementation Notes

- 测试模式开关复用现有 `window.__ENT_SIM_TEST` 与 `__toggleTestMode()`，默认关闭，不影响正常玩家。
- 所有池子过滤优先复用现有 `canTrigger` / `filterByRequire`，不新增调度器。
- 曝光惩罚改为阶梯式：轻度（1-3）小幅扣 1-2，中度（4-7）扣 3-5，重度（8+）扣 6-8，并保证 popularity 不低于 3。
- 出道判定后立即 `saveGame()`，防止刷新后状态回退。
- 旧存档迁移：新增 `migrateEntSimSave()` 在 `state.js` 中，对缺失字段兜底，避免已坏存档继续恶化。
- 不新建 UI，仅复用已有弹窗与面板；测试模式文本统一经 `escHtml()` 入 DOM。

## Agent Extensions

### SubAgent

- **code-explorer**
- Purpose: 在主要修复完成后，对 entSim 剩余剧情生成链路进行二次扫描，补全被截断的审查报告中未覆盖的事件守卫、曝光惩罚、好感度推进、弹窗队列等问题。
- Expected outcome: 输出一份剩余风险清单（文件路径、行号、问题描述、修复建议），供后续迭代使用。
