## 用户需求

针对项目现有的"压缩记忆"系统提出全面优化方案。经过代码分析和用户确认，识别出 6 个核心问题需要修复，覆盖换乘恋爱和 1v1 两种模式。

新增问题 6（用户反馈）：日记、信箱、朋友圈等"衍生物"会反复提到之前的记忆，某一样东西来回写。根源是：日记注入 20 条历史事件但去重参考只列 2 篇日记前 60 字；信箱完全无去重注入；事件日志本身可能含重复条目。

## 产品概述

优化两种游戏模式的 AI 记忆系统，解决跨天失忆、压缩信息低效、历史无限膨胀、剧情重复检测缺失、衍生物（日记/信箱/朋友圈）反复嚼旧记忆等问题。核心改善方向：1v1 模式补全跨天摘要压缩机制、压缩输出结构化、换乘恋爱历史分层衰减注入、新增重复检测校验、事件日志存储衰减、衍生物生成增加去重注入与校验。

## 核心功能

- 1v1 模式新一天时压缩昨日全文为结构化摘要，注入最近 3 天记忆
- 每日压缩从自由文本改为 JSON 结构化输出（事件/台词/约定/揭示信息分类）
- 换乘恋爱 dailySummaries 按时间距离分层衰减注入（近期完整/中期精简/远期只留约定）
- 新增剧情重复检测：新生成剧情与近期摘要做关键词重叠检查，超阈值返回 correction
- 1v1 事件日志存储软上限 200 条，超限时自动合并最早条目为"早期摘要"
- **[NEW]** 衍生物（日记/信箱/朋友圈）去重注入与校验：日记去重参考扩充到最近 4 篇全文；信箱注入最近 5 条历史消息；朋友圈去重参考补充 reply 文本；事件日志注入前做去重过滤

## 技术栈

- 语言：JavaScript (ES Modules)，Node.js 18+
- 框架：Vanilla JS + Vite
- AI API：DeepSeek (`deepseek-chat` model)
- 约束：`var` 而非 `let/const`；字符串拼接用 `+`；不引入新依赖；`escHtml()` 转义；旧存档向后兼容

## 实现方案

### 核心策略

分 5 个独立优化点，按依赖关系排序实施。所有改动基于现有 `memory.js` / `state.js` / `prompts.js` / `parser.js` 架构，不引入新模块文件。

### 关键技术决策

1. **1v1 跨天摘要复用 `compressTodayToSummary` 而非新建函数**：该函数已存在于 `memory.js:150`，只需在 1v1 的"新一天"触发点调用它，结果存入 `GS.oneHeartYesterdaySummary`。同时新增 `GS.oneHeartDailySummaries` 数组存储多天摘要（最近 3 天注入）

2. **结构化压缩输出**：修改 `compressTodayToSummary` 的 system prompt，要求 AI 输出 JSON `{"events":[],"dialogues":[],"promises":[],"revealedInfo":[]}`。解析失败时 fallback 到原文截取。注入时按类别分别标注，AI 检索效率更高

3. **分层衰减注入**：在 `prompts.js:283-288` 换乘恋爱历史注入处改造循环逻辑——最近 2 天完整、3-5 天前截取前 200 字、6+ 天前只保留 `promises` 和 `revealedInfo` 字段（需结构化数据支持）

4. **重复检测放在 `parser.js:validateOneHeartNarrative` 和 `validator.js:validateNarrative`**：提取新 narrative 的关键词（人名/地名/动作动词），与最近 3 天摘要文本做 Jaccard 相似度，超 40% 返回 correction。关键词提取用简单分词 + 长度过滤（>=2字），不引入分词库

5. **事件日志衰减**：在 `game-engine.js:1786-1790` concat 后检查长度，超 200 条时把前 100 条合并为一条 `"[早期事件] " + items.slice(0,100).join('；')`，保留后 100 条明细

### 性能与可靠性

- 压缩调用复用现有 `TOKEN_CONFIG.dailySummary`（3000 tokens），不增加配额
- 1v1 跨天压缩在新一天加载时异步执行，不阻塞 UI（用 `showLoading` 已有机制）
- 结构化 JSON 解析失败时 fallback 到 `full.slice(0, 1000)`，与现有兜底一致
- 重复检测的关键词提取复杂度 O(n)，n 为摘要文本长度，单次 <1ms
- `oneHeartDailySummaries` 数组限制 7 条（7 天），超限时 shift 最早一条
- 旧存档兼容：`migrateSave` 中所有新字段都有 undefined 兜底

## 实现备注

- **1v1 跨天压缩不阻塞 UI**：`compressOneHeartYesterday` 在 `generateOneHeartRound` 之前 await，但用 try/catch 包裹，失败时 fallback 到直接截取尾部 1000 字。`showLoading` 已在调用链上层处理
- **结构化数据向后兼容**：旧 `dailySummaries` 条目是 plain text，新条目是 JSON string。注入时先 `try JSON.parse`，失败则当 plain text 处理。分层衰减中"只保留 promises/revealedInfo"仅对 JSON 条目生效，plain text 条目退化为截取 200 字
- **重复检测防误判**：新一天场景（`isNewDay === true`）跳过检测，因为早晨场景天然与前一天有重叠元素。Jaccard 相似度用 Set 交集/并集计算，关键词过滤掉常见词（"他说""她说""看着"等，维护一个 STOP_WORDS 数组约 20 个）
- **eventLog 衰减不破坏注入**：合并后的早期摘要仍是一条 string，`prompts.js:1003` 的 `'- ' + _recentEvents[_evi]` 拼接正常工作
- **与好感度修复计划无冲突**：本计划修改的 prompts.js 区域（line 283-288 和 1007 附近）与好感度修复计划修改的区域（line 967, 1091, 1172）不重叠
