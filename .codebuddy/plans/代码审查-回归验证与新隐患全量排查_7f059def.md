## 用户需求

对《换乘恋爱 × SEVENTEEN》项目再做一次全面代码审查，目标与范围如下：

- **目标**：既回归验证 2026-07-07 那版审查里列出的旧项（BUG-01~26、IMP-01~21）是否真实落地、有无引入新回归，又独立排查此前未覆盖或新出现的 bug / 隐患。
- **范围**：全量 `src/`（含此前未审的 `ui/` 组件、`modals/` 弹窗、`ui-renderer.js`、`formatters.js`、`init.js`、`style.css`、`worlds/`、`memory/`、`parser/`、`prompts/` 子模块，以及 `core.js`/`schema.js`/`validator.js`/`story-cache.js`/`sms.js`/`screen-effect.js` 等新文件）。
- **产出**：新建一份**独立**的审查报告文件（建议 `2026-07-08-代码审查报告.md`），不修改、不覆盖现有 `2026-07-07-代码审查修复计划.md`。

## 核心审查内容

- **回归验证**：逐条核对旧 BUG/IMP 的「位置」与「修复状态」在当前代码中是否真实存在，确认修复未被新增文件/重构位置替换导致失效，识别新回归。
- **新项排查（按严重度 🔴/🟡/🟢）**：
- XSS/转义：`escHtml()` 是否在所有 AI 文本插入 DOM 前全覆盖（重点 `ui/`、`modals/`、`sms.js`、`story-cache`、`narrative-box`）。
- 状态一致性：新字段（`mood`/`brotherStance`/`oneHeartSchedule`/`secretDating`/`memberBond`/`futureConsequences` 等）是否在 `defaultGameState` + `migrateSave` 完整兜底。
- 1v1 安全分支：`buildSystemPrompt`/`buildUserMessage`/`generatePhaseNarrative`/`renderGameScreen` 开头 `if (gameMode==='oneHeart') return oneHeartVersion()` 是否完整，无 1v1 误访问 transfer-only 字段。
- 持久化：关键副作用后是否 `saveGame()`，刷新是否丢状态。
- 卡死/边界：phase 上限、选项耗尽、空数据、`undefined` 访问、`MEMBERS.find` 等容错。
- 死代码/未调用导出、规范偏离（`var` 而非 `let/const`、`+` 拼接而非模板字符串）。

## 技术方案（审查方法论，无代码改动）

### 1. 技术栈与约束

- 纯静态审查 + 精准 grep/读取，不运行构建、不修改任何文件（计划模式 + 用户确认前零改动）。
- 沿用现有项目规范作为评判基准：Vanilla JS（ESM）、`var`/`+` 拼接、`escHtml()` 强制转义、`localStorage` 存档、`GS` 引用不可替换、禁止 `alert`/`confirm`。

### 2. 实施策略

- **双轨并行**：先以 2026-07-07 文档为基线做回归核对，再对全量 `src/` 做独立逐文件排查，避免与旧审查重复又覆盖盲区。
- **精准定位**：基于 AGENTS.md 架构图与旧文档「位置」字段，用 `search_content`/`read_file` 直接跳转可疑点，减少盲目通读。
- **重点路径优先**：XSS 高危面（`ui/`、`modals/`、`sms.js`、`narrative-box.js`、`x-archive-modal.js`、`x-items-modal.js`）、状态迁移链（`state.js` → `migrateSave`/`defaultGameState`）、1v1 分支一致性（`game-engine.js`/`ui-renderer.js`/`prompts.js`）。
- **防误判**：对「已修复/无-op」类旧项（如 BUG-02/BUG-14）不仅看注释，还要核对当前代码是否真合规；对 rewrote/拆分文件（如 `parser.js` → `src/parser/`）按新位置复核。

### 3. 性能与可靠性

- 不引入新依赖、不做启发式大范围扫描造成的噪声；每条发现必须附**文件:行号**证据，便于后续定点修复。
- 报告分级：🔴 高危（玩法正确性/持久化/卡死）、🟡 中危（逻辑不严谨/语义偏差/规范偏离）、🟢 低危（健壮性/一致性/文档偏差）。

### 4. 产出结构（新建报告文件）

```
2026-07-08-代码审查报告.md
├── 一、审查范围与基线说明
├── 二、回归验证结果表
│   ├── BUG-01~26：已修复 / 回归 / 未修复（附证据）
│   └── IMP-01~21：已落地 / 部分 / 回归（附证据）
├── 三、新发现问题（按 🔴/🟡/🟢 分级）
│   └── 每条含 位置 / 现象 / 根因 / 修复建议
├── 四、修复顺序建议
└── 五、回归验证清单（可手动/实测项）
```

### 5. 架构与目录

- 仅新增 1 个报告文件，不触碰 `src/` 任何代码，不修改旧审查文档。
- 若后续用户确认修复，再依据本报告条目逐条定点修改（本次计划不含修复实现）。

## Agent Extensions

### SubAgent

- **code-explorer**
- 用途：跨多文件/多目录的精准检索与批量阅读，用于回归核对旧 BUG/IMP 位置、扫描全量 `src/` 的 `escHtml` 覆盖、状态字段兜底、`gameMode==='oneHeart'` 分支完整性等。
- 预期结果：输出每条旧项的当前代码证据（文件:行号 + 代码片段）以及新发现的疑似问题清单，作为报告撰写的事实依据。
