## 产品概述

将 1v1「只为你心动」模式的跨回合压缩记忆系统从「每10回合批量调用 AI 生成1000字整段摘要」改造为「每篇剧情生成时 AI 顺带返回事件条目」。事件条目为一句话文本，包含人物、地点、事件要素，如「女主给正主买咖啡」或「正主在练习室生病了，女主照顾他，被哥哥怀疑，哥哥让队友金珉奎送正主回宿舍」。

## 核心功能

- AI 生成每篇剧情时在 JSON 输出中顺带返回 `eventItems` 事件数组，零额外 AI 调用、零额外延迟
- 事件条目以一句话纯文本形式存入 `oneHeartEventLog`，按时间顺序累积
- 所有 1v1 prompt 注入点（剧情/聊天/朋友圈/剧场日记）改为读取事件列表注入，格式为 `- 事件1\n- 事件2`
- 近期剧情尾部衔接注入保留（去掉旧的压缩指针 oneHeartLastCompressedIdx 依赖，改为直接取尾部）
- 回顾弹窗 1v1 标签页改为「事件回顾」列表展示
- 去掉旧的异步批量压缩逻辑（callDeepSeek 压缩调用 + dailySummaries.push + promiseLog 调整）
- 换乘恋爱（经典模式）完全不受影响

## 技术栈

- 语言: JavaScript (ES Modules)，使用 var 不用 let/const，字符串用 + 拼接
- 运行时: 浏览器原生 API + Node.js 18+
- AI API: DeepSeek (deepseek-chat)
- 无新增依赖

## 实现方案

### 核心策略

在 1v1 system prompt 的 JSON 输出结构中新增 `eventItems` 字段，AI 生成每篇剧情时顺带提取本篇关键事件为一句话条目数组。解析后存入 `GS.oneHeartEventLog`，替代旧的 `dailySummaries` 批量摘要。

### 关键技术决策

1. **合并到剧情生成同一次 AI 调用**：不额外增加 AI 调用次数和延迟。`eventItems` 作为 JSON 可选字段返回，解析时容错（缺失返回空数组）。

2. **新建独立字段 `oneHeartEventLog`**：不复用 `dailySummaries`（换乘恋爱共用字段），避免格式混淆。1v1 注入点和回顾弹窗改读新字段，换乘恋爱的 `dailySummaries` 读写路径完全不动。

3. **去掉旧异步压缩逻辑**：移除 `game-engine.js:1868-1911` 的 `callDeepSeek` 压缩调用、`dailySummaries.push`、`oneHeartGenCount -= 10`、`oneHeartPromiseLog.createdAtRound` 调整。保留 `oneHeartGenCount++`（回礼/冷战/聊天回合判断依赖）。

4. **近期剧情注入简化**：去掉 `oneHeartLastCompressedIdx` 依赖（该指针不再前进），改为直接取 `todayFullText` 尾部字符截断。该指针在 state 中保留（向后兼容），但不再有写入逻辑。

5. **注入条数限制**：phase 注入最近40条事件、chat 15条、theater/diary 20条。事件条目本身短（20-50字），即使40条也仅约1000-2000字，比旧的3000字摘要大幅节省 token。

6. **向后兼容**：旧 1v1 存档中已有 `dailySummaries` 条目保留不删，回顾弹窗做 fallback 显示。

### 数据流

```
AI 生成剧情 (generateOneHeartRound)
  → JSON 输出包含 blocks + options + sceneContext + eventItems
  → parseOneHeartNarrative 解析 eventItems
  → 存入 GS.oneHeartEventLog (concat)
  → 下一轮 prompt 注入读取 oneHeartEventLog → 格式化为事件列表
  → 近期剧情尾部衔接直接取 todayFullText 尾部
```

## 实现注意事项

- `narrative-box.js:144` 使用 `oneHeartLastCompressedIdx` 渲染 consequence 列表，该指针保持 0 不变，行为不变（显示最近15条），无需修改
- `review-modal.js:200-201` 的 rescan 按钮使用 `oneHeartLastCompressedIdx` 取 todayFullText，需改为直接取尾部
- AI 可能不返回 eventItems 或返回非数组，解析时需 `Array.isArray` 校验 + fallback 空数组
- 重试场景（game-engine.js:1773-1781）的 parsed 替换后，应使用重试结果的 eventItems
- `oneHeartArchivedNarratives`（原文缓存）不再有新数据写入，已有数据保留
- `oneHeartGenCount` 继续递增（回礼 game-engine.js:1621、冷战 prompts.js:1036、聊天回合 prompts.js:1205 依赖）
