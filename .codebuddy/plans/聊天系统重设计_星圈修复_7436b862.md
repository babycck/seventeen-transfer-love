## 用户需求

### 聊天系统重设计

把3个聊天频道（哥哥/情敌/男主）统一改为**绑定式 Q&A 流程**：

1. 对方每隔几回合或每天从池子拉一个预设问题发给玩家（如"今天月末评价怎么样"）
2. 玩家看到问题后，快捷回复按钮显示**3个预设回复选项**（绑定在这个问题上，如 A 还可以吧 / B 压力太大 / C 你呢）
3. 玩家选了选项后，对方回**对应的回复**（绑定在这个选项上，如选A回"那就好。别太拼。"）

### 池子升级策略

先做 5-10 条原型测试，验证流程通了再批量改。

### 星圈修复

练习生期星圈只显示3条别人的外部热搜（starHot），不应有营业事件内容。出道后只有触发"今日营业事件"才会有星圈内容，没营业时页面保持不动。

### 已改代码处理

已改的聊天流程代码（pushPairedChat + renderPhoneChatMsgs）**先回滚到原版**，在统一改造时重写。章节蒙太奇、场景化预设"谢谢哥"→"谢谢"、日志等保留。

## 池子结构升级

### 新格式（3个频道统一）

```js
{
  from: 'opp',           // 'opp'=对方发, 'you'=玩家发（仅哥哥/情敌频道有）
  msg: '今天月末评价怎么样',
  replies: ['还可以吧', '压力太大', '你呢'],
  responses: ['那就好。别太拼。', '压力大就说出来——哥在。', '我？老样子。但你比哥重要。'],
  time: '19:30',
  require: 'debut'       // 可选门控
}
```

## 聊天流程改造（3个频道统一）

### 推送层

- **pushPairedChat** (ui.js:2987)：推 msg 时，把 `entry.replies` + `entry.responses` 存到 `_entSimPendingChat[ch]`
- **tryPushMLDailyStarter** (ui.js:2957)：男主频道也改为存 `_entSimPendingChat.maleLead`（当前只推 msg 不存 pending）

### 渲染层

- **renderPhoneChatMsgs** (ui.js:~1882)：3个频道统一逻辑——有 `pendingChat[ch]` 时用 `pendingChat.replies` 作为预设按钮；无 pendingChat 时回退到现有逻辑

### 回复层

- **__quickReply** (ui.js:~1756)：3个频道统一逻辑——选 `replies[idx]` 后回 `pendingChat.responses[idx]`；旧格式无 responses 时回退到 acks 池

### 数据流

```
pushPairedChat/tryPushMLDailyStarter
  → 推 msg 到聊天历史
  → 存 {replies, responses} 到 pendingChat[ch]

renderPhoneChatMsgs
  → 有 pendingChat → 用 replies 作预设按钮
  → 无 pendingChat → 回退到 getChatPresetsByChannel

__quickReply(ch, idx)
  → 选 replies[idx]
  → 回 responses[idx]（新格式）或随机 acks（旧格式）
  → 清除 pendingChat[ch]
```

## 星圈修复

### renderFeedbackContent 加 isDebut 门控

- 练习生期（`debutDay=0`）：只展示 `dailyBuzz.starHot`（3条外部热搜），**不展示** `_entSimFanEvents` 和 `fanReactions`
- 出道后：展示 `_entSimFanEvents`（营业事件帖）+ `fanReactions`

### 脏数据清理

- `entSim` 状态加载/初始化时，若 `debutDay=0` 且 `_entSimFanEvents` 非空，清空（练习生期不应有营业事件）
