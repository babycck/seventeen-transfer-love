## 用户需求

1v1 模式下日记和朋友圈不再自动生成。需要修复使它们恢复正常的自动触发。

## 根因

`generateOneHeartRound()` 在第 1715 行设置 `GS._isGenerating = true`，整个 try 块（1717-2015）期间锁未释放。日记（第 1838 行 `await generateDiary()`）、朋友圈（第 1845 行 `await generateMoment()`）、秘密信件（第 1993 行 `await generateLetter()`）都在 try 块内调用，但这三个函数开头都检查 `if (GS._isGenerating) return null;`，导致每次都被自己的锁挡住，直接返回 null，永远不生成。

## 影响范围

- `generateDiary()` — 第 2635 行检查锁，被挡住
- `generateMoment()` — 第 2677 行检查锁，被挡住
- `generateLetter()` — 第 2802 行检查锁，被挡住（用户尚未发现，因为需要 genCount >= 5 才触发）
- `generateMessage()` — 不检查锁，不受影响

## 修复目标

- 1v1 模式下每 3 段剧情自动生成日记，日记 tab 出现红点
- 每 3-5 段剧情自动生成朋友圈，朋友圈 tab 出现红点
- 秘密信件恢复正常触发
- 主剧情生成失败时不触发日记/朋友圈/信件（异常 throw 后 finally 执行，但 deferred 标志未设置）
- 构建通过、lint 无错

## Tech Stack

- JavaScript (ES Modules), Vanilla JS + Vite
- 无新依赖，纯逻辑修复

## 修复方案：Deferred Flag 模式

### 核心思路

在 `generateOneHeartRound()` 的 try 块内，将 `await generateDiary()` / `await generateMoment()` / `await generateLetter()` 的直接调用替换为设置延迟标志（`_needDiary` / `_needMoment` / `_needLetter`）。在 finally 块释放锁之后，根据标志执行实际的 AI 生成调用。

### 为什么选择这个方案

1. **最小改动**：不修改 `generateDiary` / `generateMoment` / `generateLetter` 自身的锁逻辑（它们仍需保护用户手动点击时的重入）
2. **安全**：标志在 try 块内设置，主剧情失败（throw）时标志不会被设置（throw 前未执行到的代码不会设标志），自然跳过延迟生成
3. **不阻塞渲染**：finally 块先执行 `window.__renderAll()` + `hideLoading()`，用户立即看到剧情，然后后台静默生成日记/朋友圈
4. **错误隔离**：每个延迟调用独立 try-catch，互不影响

### 修改文件

- `src/game-engine.js` — 仅修改 `generateOneHeartRound()` 函数（第 1712-2024 行）

### 具体改动

**1. 在 try 块前声明延迟标志（第 1716 行之后）**

```js
var _needDiary = false;
var _needMoment = false;
var _needLetter = false;
```

**2. try 块内：替换直接调用为设标志**

- 第 1838 行 `await generateDiary();` → `_needDiary = true;`
- 第 1845 行 `await generateMoment();` → `_needMoment = true;`
- 第 1993 行 `await generateLetter();` → `_needLetter = true;`

计数器递增和条件判断保留原位（只在主剧情成功时才计数）。

**3. finally 块之后（第 2023 行 `}` 之后，函数结束前）添加延迟执行**

```js
// 锁已释放，执行延迟生成
if (_needDiary) {
  try { await generateDiary(); } catch(e) { console.warn('[1v1] diary deferred error:', e); }
}
if (_needMoment) {
  try { await generateMoment(); } catch(e) { console.warn('[1v1] moment deferred error:', e); }
}
if (_needLetter) {
  try { await generateLetter(); } catch(e) { console.warn('[1v1] letter deferred error:', e); }
}
if (_needDiary || _needMoment) {
  window.__renderAll && window.__renderAll();
}
```

### 注意事项

- 回礼检测 `checkPendingReturnGifts()` 保持在原位（不依赖锁，不是 AI 生成）
- `generateMessage()` 无锁检查，不受影响，保持在原位
- 延迟生成期间 `GS._isGenerating` 会被 generateDiary/generateMoment 再次设为 true，阻止用户在此期间触发新剧情轮次（正确行为）
- 延迟生成完成后调用 `window.__renderAll()` 刷新红点提示
