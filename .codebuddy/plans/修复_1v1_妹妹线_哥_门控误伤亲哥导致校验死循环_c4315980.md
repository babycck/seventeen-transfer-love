## 用户需求

用户在 1v1「只为你心动」的「队友的妹妹 + 心动小屋同居」设定下推进初识期剧情时，控制台反复出现 `[1v1] 重试后仍有校验矛盾` 警告，提示两条「称呼门控」：

1. 禁止称男主"哥/哥哥/형"，请改为"全圆佑前辈"；
2. 队友的妹妹设定下初识期须称男主"全圆佑前辈"，禁止直呼名字。

用户期望：消除校验误判，使剧情不再因称呼门控陷入无效重试。

## 补充说明（非功能需求，属排查结论）

- 控制台同时报 `vite server connection lost` 与 `net::ERR_CONNECTION_REFUSED (5174)`，说明 dev 服务器已停止，浏览器加载的是旧打包；此部分需用户重启 `npm run dev` 才能加载最新修复，不属于代码改动。
- 上一轮已修复 `validator.js:81`（放行正确写法"全圆佑前辈"），该修复已写入源文件，但未被挂掉的 dev 服务器加载，重启后即生效。
- 本轮真正需要修复的代码缺陷是 `validator.js:72-74` 的「哥哥/哥，/형」无差别拦截，它误伤了剧情中女主对亲哥哥称呼的"哥哥"，导致 AI 被强制要求把亲哥改成男主名而无法满足，进而反复重试矛盾。

## 核心修复点

修正 1v1 妹妹线称呼门控中"哥/哥哥/형"的判定：从「拦截所有哥哥/哥，/형」改为「仅当男主名字后接 哥/형（如全圆佑哥、圆佑哥、Wonwoo哥）才拦截」，并彻底豁免亲哥的"哥哥"（妹妹设定下亲哥是独立人物，永不应被改成男主名）。

- 仅涉及单文件修改：`src/validator.js`
- 遵循 AGENTS.md 约定：使用 `var`、字符串拼接（不使用模板字符串）、不引入新依赖

## 实现方案

### 总体策略

`checkOneHeartAddressing()` 是 1v1 妹妹线「基于内容的代码硬兜底」门控（首行 `if (GS.gameMode !== 'oneHeart' || !isSisterSetting()) return corrections;` 已将其隔离在 1v1 妹妹设定内，transfer 模式与其他 1v1 设定不受影响）。本次为最小、聚焦改动：仅重写「哥/哥哥/형」判定块（行 72-74），对齐 transfer 模式 `checkAddressViolation` 已有的「X哥」模式匹配 + 亲哥豁免逻辑，避免 1v1/transfer 行为分歧。

### 根因

原代码：

```js
if (content.indexOf('哥哥') >= 0 || content.indexOf('哥，') >= 0 || content.indexOf('형') >= 0) {
  corrections.push('[称呼门控] 禁止称男主"哥/哥哥/형"，男主是前辈不是亲哥。请改为"' + memberName + '前辈"或直接描写动作。');
}
```

妹妹设定下 `isSisterSetting()` 为真意味着 `GS.oneHeartRelationCharacter.role === '哥哥'`（utils.js:31-34），亲哥哥是剧情核心人物，正文中「哥哥」几乎一定指亲哥。该规则无差别拦截并强制改为男主名，导致：

- AI 写亲哥的「哥哥」被判违规；
- 重试一次仍矛盾（亲哥不可能被改成"全圆佑前辈"）；
- game-engine.js:2430-2433 二次校验告警并采用仍判违规结果 → 用户所见「重试后仍有校验矛盾」。

### 修复代码（替换行 72-74）

```js
  // 妹妹线：男主是前辈不是亲哥。仅当男主被叫成"X哥/X형"（如"全圆佑哥""圆佑哥""Wonwoo哥"）才拦截；
  // 女主对亲哥哥称"哥哥"是允许的（亲哥是另一个人），绝不改成男主名。
  if (member) {
    var _fn = member.name.charAt(0);
    var _patterns = [_fn + '哥', member.name + '哥'];
    if (member.stageName) {
      _patterns.push(member.stageName + '哥');
      _patterns.push(member.stageName + '형');
    }
    _patterns.push(member.name + '형');
    for (var _pi = 0; _pi < _patterns.length; _pi++) {
      if (content.indexOf(_patterns[_pi]) >= 0) {
        corrections.push('[称呼门控] 禁止称男主"' + _patterns[_pi] + '"，男主是前辈不是亲哥。请改为"' + memberName + '前辈"或直接描写动作。');
        break;
      }
    }
  }
```

语义变化：

- 原规则会把亲哥「哥哥/哥，/형」误判为违规；新规则只拦「男主名+哥/형」，亲哥「哥哥」不在 patterns 内 → 不再误判。
- 男主被叫成「全圆佑哥/Wonwoo哥」等仍被正确拦截并重试（合理行为保留）。
- 与 transfer 模式 `checkAddressViolation`（validator.js:330-352）的「firstName+'哥' / target.name+'哥'」模式 + `_isBrother` 豁免逻辑一致。

### 性能与可靠性

- 仅字符串 `indexOf` 遍历少量 patterns，复杂度为 O(n·k)（n=正文长度，k≤5），无性能影响。
- 不改变正常 1v1 妹妹线行为（正确称"全圆佑前辈"已由上一轮 line-81 修复放行），不影响 romanceStage>=1（欧巴解锁）路径、不影响非妹妹设定、不影响 transfer 模式。
